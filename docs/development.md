# 開発と確かめ

コードを変えたときの確認と、安全性の点検です。開発するときの決まり（必ず守ること、作業の決まり、はまりどころ）は [AGENTS.md](../AGENTS.md) にあります。

[README に戻る](../README.md)

## コードを変えたときの確認（料金なし）

コードを変えたら、次の 3 つを通します（ADR-0034）。GitHub に送ると、同じ 3 つを CI（GitHub Actions）も流します（ADR-0036）。

```bash
uv run ruff format .
uv run ruff check .
uv run pytest -q
```

- `ruff format` は、改行や空白などの書き方を揃えます（整形）。
- `ruff check` は、誤りのもとになりやすい書き方、分岐が多すぎる関数、セキュリティの心配がある書き方（bandit と同じ点検）を見つけます。`--fix` を付けると、直せるものを直します。
- 誤検知には、`# noqa: <番号>  理由` と、理由を添えて書きます。
- 依存ライブラリを変えたら、`bash scripts/audit_deps.sh` で既知の脆弱性を調べます。
- 決めたこと（機能を足す・変える・やめる、など）は、`docs/adr/` に残します（ひな形は `docs/adr/template.md`）。
- 変えたところは `git status` と `git diff` で見られます。記録は GitHub の非公開のリポジトリに置いています（ADR-0035）。

## 画面の回帰確認（料金なし）
画面と同じ通信（ログイン・チャットの接続・API）で、確認のボタン、コードの実行、データベース、ガードレール、モデルの切り替え、定時実行、スキルの提案、過去のチャット、返事の照合、接続元の検査、用途パックと MCP（HTTPS の社内 API の見本）などを、偽のモデルでまとめて確かめます。API キーは要らず、料金もかかりません。
```bash
bash tests/e2e/regress.sh
```
- 10 分ほどかかります。確認ごとに、使い捨てのデータベースとコンテナを作り、終わったら消します。手元の Langfuse の PostgreSQL と、動いているアプリには触れません。
- 先にイメージを作っておきます（`docker compose build`）。手元の `src/`・`tests/`・`config/`・`packs/` を重ねて使うので、イメージを作り直さなくても、手元の変更を確かめられます。依存（`pyproject.toml`）を変えたときだけ、作り直します。
- 一部だけ流すときは、名前を並べます（例: `bash tests/e2e/regress.sh origin grounding`）。
- 結果は `logs/e2e/` に残ります。すべて通れば、終了コードは 0 です。

## 安全性の点検（OWASP LLM Top 10）
OWASP LLM Top 10（2025 年版）の項目ごとに、合格基準と結果をまとめてあります（`docs/adr/0020-owasp-llm-top10-review.md`）。

### 依存ライブラリの既知の脆弱性
依存ライブラリを変えたときは、既知の脆弱性がないかを確かめます。アプリのライブラリと、コードを実行する環境のライブラリを、まとめて調べます。
```bash
bash scripts/audit_deps.sh
```
- 結果は `logs/audit/` に残ります。終了コードは、0 が「見つからなかった」、1 が「見つかった」、2 が「調べられなかった」です。
- 調べる先は OSV（無料の脆弱性のデータベース）で、送るのはライブラリの名前と版だけです。料金はかかりません。
- ライブラリを変えなくても、脆弱性はあとから見つかります。毎日、自動で調べるように、Mac に登録します（毎日 9 時。見つかったときだけ通知が出ます。時刻は `AUDIT_HOUR=7` のように付けて変えられます）。
```bash
bash scripts/schedule_audit.sh install
```
  状態と最後の結果は `bash scripts/schedule_audit.sh status`、解除は `remove` です。詳しくは `docs/adr/0024-scheduled-dependency-audit.md` にあります。

### 指示の乗っ取りへの強さを測る（料金あり）

ファイル・データベースの値・Web 検索の結果に「AI への指示」を仕込み、エージェントが従うか、従ったときに守りを抜けるかを数えます（攻撃は 21 種類。基準は、貫通率 20% 以下）。
```bash
uv run python -m evals.redteam --selftest
uv run python -m evals.redteam --model all
```
- 1行目は、点検の仕組みを偽のモデルで確かめるだけで、料金はかかりません。
- 2行目は、本物のモデルを使うので、API の料金がかかります。画面で選べる3つのモデルを測って、約 1 ドルです（2026-11-15 の実測で約 0.95 ドル。`--model all` を外すと、既定のモデルだけを測ります。Opus 5.5 だけなら、約 0.5〜0.65 ドル）。実行の前に目安を表示して、確認を求めます。上限（既定は 10 ドル）に達したら、途中でやめます。
- 2026-11-15 の結果: 画面で選べる 3 つのモデル（Opus 5.5、Sonnet 5.5、Haiku 5.5）とも、従った 0/21、貫通 0/21（`docs/adr/0020-owasp-llm-top10-review.md`）。料金は、3 つ合わせて約 0.95 ドルでした。プロンプトを変えたあとの測り直しでも、同じ結果でした（約 0.69 ドル）。
- 本物の作業フォルダ・長期メモ・Web・データベースには触れません。使い捨てのフォルダと、外につながない代わりの役を使います。
- 結果は画面に出て、詳しい記録が `logs/redteam/` に残ります。プロンプト、モデル、ツールを変えたときは、測り直してください。

### 誤情報（作り話）を測る（料金あり）

手元のファイルと検索結果に、答えがある質問・ない質問・コードを実行できない質問（12 問）を送ります。正しい値を答えるか、答えがないときに「ない」と言えるか、ファイルや検索結果にない数や出典を書かないかを数えます。判定に、別のモデルは使いません。
```bash
uv run python -m evals.factcheck --selftest
uv run python -m evals.factcheck --model all
```
- 1行目は無料（偽のモデル）。2行目は API の料金がかかります（3 つのモデルで約 0.5 ドル）。
- 基準は案です（正答率 90% 以上、「ない」と言えた割合 90% 以上、作り話 10% 以下）。詳しくは `docs/adr/0025-misinformation-check.md` にあります。
- 2026-11-15 の結果: 3 つのモデルとも、正答 6/6、「ない」と言えた 6/6、作り話 0/12（2 回測った。どちらも、記録を読んで判定の規則を直したあとの判定）。
- 読んだ表から出せる簡単な計算（合計、平均、差など）が合っている数と、確かめ先として案内しただけの URL は、作り話に数えません。画面の「作り話に数えなかったもの」に出るので、記録の返事を読んで確かめてください。
- 詳しい記録は `logs/factcheck/` に残ります。
