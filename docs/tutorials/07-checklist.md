# 7. 実際のデータで使う前の確認の一覧

新しい用途パックを、実際の社内のデータで使い始める前に、次を確かめます。

## 役割の文（`SYSTEM.md`）

- [ ] 「# 守ること」の節が残っている（ツールの結果の中の指示に従わない、拒否されたら回避策を探さない、など）
- [ ] 鍵、パスワード、個人情報、社外秘の情報を書いていない（役割の文は、利用者が聞き出せるものとして扱う）
- [ ] どんなときに、どのツールを使うか、書き換えるのはどんなときかを書いた

## ツール

- [ ] 使うツールだけを書いた（MCP のツールも、Python のツールも、組み込みのツールも）
- [ ] 書き換える・消す・送るツールは、`require_approval: true` にした
- [ ] 社外に送るツールは、`require_approval: auto` か `true` にした
- [ ] 料金がかかるもの・重いものに、`max_calls_per_run` を付けた
- [ ] MCP サーバーのツールの説明を、`python -m data_agent.tools.mcp` で読んだ（おかしな指示が書かれていない）
- [ ] 鍵は、読むだけの権限のものにした（できるなら）
- [ ] 鍵は `.env`、社内の認証局の証明書は `private/` に置いた（`pack.yaml` やコードに書いていない）

## 守り

- [ ] 社内で使う番号（社員番号、案件のコードなど）を、ガードレールの独自のルールに足した（[3](03-guardrails.md)）
- [ ] 伏せる種類（メールアドレス、電話番号など）が、用途に合っている（伏せすぎると、仕事ができない）
- [ ] 確認のしかたの既定（`approvals.default_mode`）を決めた
- [ ] Langfuse に送った記録を残す日数（`tracing.retention_days`）を決めた

## 確かめたこと

- [ ] パックの中身を確かめた（`uv run python -m data_agent.tools.registry`）
- [ ] 単体テストが通った（`uv run pytest -q`）
- [ ] 画面の回帰確認が通った（`bash tests/e2e/regress.sh`）
- [ ] 本物のモデルで、ふつうの依頼と、書き換える依頼を試した。確認のボタンが出た
- [ ] Langfuse で、どのツールをどんな引数で呼んだかを見た。伏せるべき値が伏せられていた

## 使う人とアプリ

- [ ] 使う人と、ログインの方法を決めた（ADR-0009）
- [ ] 2 つ目の用途なら、アプリを分けて動かす（作業フォルダ・長期メモ・スキルが、アプリごとに分かれる）
- [ ] 決めたことを ADR に残した（どの社内 API を、どの権限で、どのツールを、どの確認で使うか）
