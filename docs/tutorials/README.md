# チュートリアル: data_agent を、別の用途のエージェントにする

data_agent は、チャットエージェントの「土台」として使えます。
守り（ガードレール、操作の前の確認、回数の上限、監査ログ）と、運用（会話の保存、定時実行、スキル、Langfuse）は、どの用途でも同じものを使います。
用途ごとに違うもの（役割の文、使うツール、つなぐ社内のシステム）だけを、**用途パック**（`packs/<名前>/`）に書きます（ADR-0032）。

```
data_agent/
├── config/security.yaml      守りの設定（どの用途にも共通）
├── packs/
│   ├── data/                 用途パック「データ分析」（いま毎日使っているもの）
│   │   ├── pack.yaml         名前・あいさつ・使うツール・MCP サーバー
│   │   └── SYSTEM.md         役割の文（システムプロンプト）
│   └── internal_api_example/ 用途パックの見本「受注照会」（社内 API を MCP でつなぐ例）
│       ├── pack.yaml
│       ├── SYSTEM.md
│       └── tools.py          Python で書いたツール
└── .env                      鍵と、どのパックを使うか（AGENT_PACK=…）
```

## 言葉

| 言葉 | 意味 |
|---|---|
| 用途パック | 用途ごとに違うものをまとめたフォルダ（`packs/<名前>/`）。`.env` の `AGENT_PACK` で、どれを使うかを選ぶ |
| 役割の文 | モデルに最初に渡す指示（システムプロンプト）。パックの `SYSTEM.md` |
| ツール | エージェントが使える操作。組み込み（コードの実行、データベース、Web 検索）、Python で書いたもの、MCP サーバーのもの、の 3 種類 |
| 扱い | ツールごとの決まり。実行の前に確かめるか、1 回の依頼で何回まで呼べるか、など（`tools/registry.py` の `ToolPolicy`） |
| MCP | Model Context Protocol。エージェントにツールを足すための共通の決まり。社内の API を MCP サーバーとして公開すれば、設定だけでつなげる |
| 確認（承認） | 操作の前に、画面にボタンを出して、利用者に「実行してよいか」を聞くこと |
| ガードレール | 鍵や個人情報（メールアドレス、電話番号など）を見つけて、伏せる（マスクする）仕組み |
| 社内の認証局 | 社内のサーバーの証明書を発行するところ。その証明書（`ca.crt` など）を `ca_file` に指定すると、社内のサーバーに HTTPS でつなげる |
