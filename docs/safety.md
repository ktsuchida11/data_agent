# 守りの仕組み

勝手な操作、料金のふくらみ、鍵や個人情報の流出を防ぐ仕組みと、その設定です。守りの一覧（どのファイルが何を防ぐか）は [architecture.md](architecture.md) の「5. 守りの一覧」、OWASP LLM Top 10 での点検は `docs/adr/0020-owasp-llm-top10-review.md` にあります。

[README に戻る](../README.md)

## 操作の前の確認（承認）
エージェントが操作を実行する前に、画面で「実行してよいですか？」と確かめます。どこまで確かめるかは、入力欄の設定ボタンから、チャットごとに選べます。

| 操作 | 標準 | 毎回確認 |
|---|---|---|
| ファイルの削除 | 確認する | 確認する |
| 長期メモ（`memories/`）への書き込み | 確認する | 確認する |
| ファイルの作成、書き換え | 確認しない | 確認する |
| Web 検索 | 外に出したくない情報らしいものがあるときだけ確認する | 確認する |
| コードの実行、データベースの問い合わせ | 確認しない | 確認する |
| 読むだけの操作（ファイルを読む、表の一覧） | 確認しない | 確認しない |

- 確認の画面には、何をするか、なぜ聞いているか、中身（書き込む内容、コード、SQL、検索の質問文）が出ます。
- 答えは4つです。「承認」「承認（このチャットでは以後確認しない）」「拒否」「拒否して理由を伝える」。理由を書くと、エージェントに伝わります。
- 「以後確認しない」は、削除と長期メモへの書き込みには出ません。チャットを開き直すと、取り消されます。
- 外に出したくない情報らしいものがある Web 検索には、「以後確認しない」は出ません。
- 10 分以内に答えないと、実行しません。確認を待ったまま画面を閉じた場合は、チャットを開き直すと、もう一度聞かれます。
- サブエージェントの操作も、同じように確かめます。調べるだけのサブエージェントは、書き込みができません。
- 新しいチャットは「標準」で始まります。既定を変える、利用者が切り替えられないようにする、「以後確認しない」を出さない、といった設定は、`config/security.yaml` の `approvals` にあります。

詳しくは `docs/adr/0021-approvals-human-in-the-loop.md` にあります。

## 回数の上限
モデルが同じ操作を繰り返し続けて、料金がふくらむのを防ぎます。1回の依頼で、モデルを呼べるのは 60 回、ツールを呼べるのは 120 回までです（`config/security.yaml` の `limits`）。
サブエージェントの分と、確認のあとの続きも、同じ1回の依頼として数えます。上限に達すると、その旨を表示して止まります。「続けて」と送ると、続きから進みます。

## Web 検索の前の確認
Web 検索の質問文は、検索のために外部に送られます。送る前に質問文を調べて、次のものがあるときだけ、画面で確かめます。見つからなければ、確かめずに検索します。

- **手元のデータの写し:** このチャットで読んだファイル・データベースの結果などにあって、自分では書いていない番号やコード、表の値（取引先の名前など）、長い文。
- **見張る言葉:** `private/watch_terms.txt` に書いた言葉と、データベースの顧客の名前などの列の値。自分で書いた場合も確かめます。

確認の画面には、見つかったものと、どこにあったかが出ます。

- **見張る言葉の一覧は、自分で作ります。** `private/watch_terms.example.txt` を `private/watch_terms.txt` という名前で写して、1行に1つずつ書きます。`private/` はイメージに入らず、エージェントからも読めません。書き換えると、次の検索から使われます。「株式会社」などを除いた形（「はまなす商事」）も見張ります。
- **データベースの顧客の名前も見張れます。** 名前の列を `config/watch_columns.<データベース名>.txt` に `表.列` と書いて、`bash scripts/setup_data_db.sh <データベース名>` をもう一度実行します（練習用のデータベースでは `customers.name` が書いてあり、`--sample` で実行します）。その列だけを読める別のロール（`coding_agent_screener`）ができ、アプリが 10 分ごとに読み直します。名前はファイルに書き出しません。初めて実行したときは、`.env` に接続情報が足されるので、アプリを作り直します。データベースに届かないときは、どの検索も確かめます。
- **定時実行では、怪しい検索だけを自動で拒否します。** ふつうの検索は行います。
- **見つけられないものもあります。** 言い換えたもの（「4.82 億円」など）や、ローマ字にした名前は、見つけられません。ファイルの見出しやログのエラー番号を質問に使うと、怪しくなくても確かめることがあります。

詳しくは `docs/adr/0022-web-search-screening.md` にあります。

## ガードレールと監査ログ
形が決まっている情報を見つけて、モデルや保存先に流れないようにします。設定は `config/security.yaml` の `guardrails` にあります。

| 種類 | 既定の扱い |
|---|---|
| 秘密情報（API キー、トークン、秘密鍵） | マスクする。含む内容のファイルへの書き込みは拒否する |
| クレジットカード番号、マイナンバー | マスクする |
| メールアドレス、電話番号、口座番号 | マスクする |

- 守る場所は、利用者の入力、ツールの結果（読んだファイルの中身など）、モデルの返事の3つです。
- マスクしたところは `[マスク済み:秘密情報]` のように表示されます。
- 全角で書いたものや、日本語に続けて書いたもの（「電話は０３（１２３４）５６７８です」）も見つけます。口座番号は、「口座」「普通」などの言葉に続く 7 桁の数字だけです。
- マスクは、アプリの全体に効きます。メールアドレスや電話番号を扱う作業（連絡先の一覧を作るなど）をさせたいときは、`email` や `phone` を `log`（記録だけ）に変えます。
- 独自形式のパスワード、氏名、住所のように、形が決まっていないものは見つけられません。データベースの個人情報は、列ごとに読めなくして守ります（[使い方](usage.md) の「データベースからデータを取る」）。

監査ログは、「誰が・いつ・何をしたか」を1件1行の JSON で標準出力に出します。`"log": "audit"` で始まる行です。会話の中身や、見つけた値そのものは記録しません（`docs/adr/0012-guardrails-and-audit-log.md`）。

## 返事の数の照合（作り話の注記）
データを読んだ回の返事について、返事の数と URL が、読んだ結果やこれまでの発言にあるかを照合します。データを読んだ回とは、データベース・Web 検索・コードの実行を使った回と、CSV などのファイルを読んだ回です。見つからないものがあれば、返事の下に注記を出します。返事は止めません。
- 読んだ表から出せる簡単な計算（合計・平均・差など）は、合っていれば注記を出しません。
- 「〜で確かめてください」「〜で確認できます」のように、確かめ先として案内しただけの URL にも、注記を出しません。
- 注記は画面と保存した会話にだけ付き、モデルには渡りません。
- ツールを呼ぶ前に話した文も含めて、その回の返事をすべて照合します。注記は、その回の最後の返事の下に 1 つだけ出ます。
- 定時実行の返事も、同じ決まりで照合します。注記は、結果のチャットの返事の下に残ります。
- 設定は `config/security.yaml` の `grounding` にあります（`enabled: false` で止められます）。
- 数のない作り話（「増えました」など）や、根拠にある数の取り違えは見つけられません（`docs/adr/0026-grounding-note-on-replies.md`）。

## ログインの失敗の回数の制限
同じ接続元から続けてログインを試すと、しばらく受け付けません。コードを実行する環境に仕込まれたコードが、パスワードを総当たりで試すのを防ぐためです（`docs/adr/0038-login-throttle-license-and-security-policy.md`）。
- 続けて 5 回まで試せます。使い切ると 1 分間受け付けず、そのあとも試すたびに、待つ時間が倍になります（最大 15 分）。ログインに成功すると、数え直します。
- 受け付けないあいだは、正しいパスワードでも入れません。時間をおいて、もう一度試してください。
- 数えるのは接続元ごとです。仕込まれたコードが失敗を重ねても、画面を開いている人は締め出されません。
- 数はアプリのメモリにだけ持ちます。急ぐときは、アプリを起動し直すと数え直します。
- 失敗が続いて受け付けなくなったときに、監査ログに `login_throttled` が 1 行出ます。
- 回数と時間は、`config/security.yaml` の `login` で変えられます（変えたら作り直します）。

## 接続元の検査
画面を開いた場所（オリジン）が、`.chainlit/config.toml` の `allow_origins` にない通信は、チャットの接続も API も断ります。同じ Mac で動く別のアプリ（Langfuse の画面など）のページから、ログイン中のあなたとしてチャットにつながれるのを防ぐためです。
- いまの一覧は `http://127.0.0.1:8000` と `http://localhost:8000` です。別の URL で開くときは、一覧に足してください（足さないと、画面がつながりません）。
- HTTPS で公開したときは、ログインのクッキーに `Secure` を付けます（`docs/adr/0027-origin-check-and-secure-cookie.md`）。

## エージェントから見えるもの
| 仮想パス | 実体 | 権限 |
|---|---|---|
| `/` | `workspace/` | 読み書き可（`.env`・鍵ファイル・`.git/` は読み書き禁止、削除は必ず確認） |
| `/memories/` | `memories/` | 読み取り可、書き込みは必ず確認 |
| `/skills/` | `skills/` | 読み取りのみ |

`config/`・`.env`・`src/` はどこにもマウントしていないので、エージェントからは見えません。
調べるだけのサブエージェント（`explorer`）は、どこにも書き込めません（読むだけ）。

コードの実行（`run_python`）は、この仮想パスを直接は見られません。エージェントが渡したファイルだけを使い、作ったファイルは `/outputs/` に保存されます。
データベースの問い合わせの結果（CSV）も、`/outputs/` に保存されます。
