data_agent 仕組みの地図

社内のデータ（ファイルやデータベース）を、Claude が調べて分析し、まとめるチャットアプリ「データ分析エージェント」です。集計や表・グラフ作りのためにコードも実行し、Web も検索します。このページは、何が動いていて、1 回の依頼がどこを通るかを、図で示します。別の用途のエージェントの土台にもなります（用途パック。2026-11-17）。

コンテナのつながり

動いているもの

アプリが書き込める場所は限られています。作業フォルダ（workspace/）・長期メモ（memories/）・手順書（skills/）と、一時フォルダだけです。

PostgreSQL は Langfuse のものを借りています。手元だけの構成です。AWS に移すときは、別に用意します（ADR-0009）。

練習用のデータは、読むだけの権限で読みます。メールアドレスや電話番号などの列は、データベースの側で読めなくしてあります。

社内の API には、起動のときにつなぎます。鍵が違う、証明書を確かめられない、などでつながらなければ、理由を知らせて起動を止めます（ADR-0033）。手元で試すための見本（internal-api-example）は、--profile example のときだけ起動します。

定時実行の流れ

チャットからの使い方

入力欄の / から「定時実行」を選び、「分 時 日 月 曜日」の 5 つと、依頼文を続けて送ります。内容を確かめるボタンが出るので、「登録する」を押すと予定になります。

0 9 * * 1 weekly-report のスキルで、先週の売上をまとめて

例です（毎週月曜の朝 9 時）。weekly-report は、登録したスキルの名前に置き換えます。

時刻の書き方意味（日本時間）
0 9 * * 1-5平日の朝 9 時
30 8 * * 1毎週月曜の 8 時 30 分
0 18 1 * *毎月 1 日の 18 時
*/30 * * * *30 分ごと（間隔は 5 分以上）

動くのは「依頼文」です。決まったスキルやタスクを指定して動かす専用の仕組みではありません。時刻が来ると、登録した依頼文を、画面と同じエージェントにそのまま渡します。

スキルも使われます。依頼文がスキルの説明に当てはまれば、エージェントはそのスキルの手順で進めます。確実に使わせたいときは、上の例のように、依頼文にスキルの名前を書きます。

ふつうの会話で頼んでも、予定は作られません。エージェントには予定を作る道具を持たせていません。登録は、/ の「定時実行」から、人がボタンを押したときだけです。言葉での登録（「毎朝 9 時に」）には、まだ対応していません。

LangChain の中で起きていること

定時実行は、画面と同じエージェントを、画面の代わりに「見張り」が動かします。エージェントは、LangChain の Deep Agents で組み立てた LangGraph のグラフです。上の図の③（無人で実行）の中では、次の順にやりとりします。

LangChain の部品何をするか定時実行での使い方
Deep Agents
create_deep_agent		エージェントを組み立てる部品。道具・手分け役（サブエージェント）・長期メモ・手順書・ファイルの権限を、まとめて組み込む画面と同じものを使う。モデルごとに 1 つ作って、使い回す（agent.py）
LangGraph のグラフエージェントの中身。「モデルを呼ぶ」と「道具を動かす」の 2 つの段を、返事が決まるまで行き来する見張りが astream で動かし、途中経過（どの道具を呼び、何が返ったか）を受け取る。手分け役の分も集めて、照合の根拠にする
thread_id会話の番号。会話の状態は、この番号ごとに保存される実行のたびに新しく作る。それが「定時実行」グループのチャットになる
チェックポイント
AsyncPostgresSaver		グラフの状態を、段を進むたびにデータベースに保存する結果のチャットを開くと、その状態から続きを話せる。止まったところからの再開にも使う
ミドルウェアモデルを呼ぶ前後や、道具を動かす前に割り込む部品守り（マスク、Web 検索の前の確認、回数の上限）は、画面のときと同じものが毎回かかる
確認待ち
HumanInTheLoopMiddleware・interrupt		確認が要る道具（削除、長期メモへの書き込み、怪しい Web 検索）の前で、グラフを止める画面ではボタンを出す。定時実行では確かめる人がいないので、止まったら「拒否」を返す
再開の命令
Command(resume=…)		止まったグラフに答えを渡して、続きを動かす拒否と、その理由（「定時実行では利用者が確認できないので、この操作は実行しませんでした」）を渡す
コールバック（Langfuse）グラフの中で起きたことを、外に記録する記録に scheduled の印を付けて、画面の会話と分けて見られるようにする

動かし方は 2 通りあります。ふだんは、アプリの中の見張りが 30 秒ごとに時刻を見ます。外から 1 回だけ起動する形（python -m data_agent.features.schedule_runner）もあり、AWS では EventBridge がこれを時刻に起動する予定です（ADR-0006）。中身は同じです。

同じ回を二重に動かしません。予定を確保するときに「次の実行時刻」を書き換え、書き換えられた 1 か所だけが実行します。止まっていた間に過ぎた回は、まとめて 1 回だけ実行します。

同時に動かすのは 2 つまでです。時刻が重なった予定は、2 つずつ順に実行します。

手順書を増やす

スキル（手順書）の足し方

スキルは、「こういう作業のときは、この手順で進める」を書いた手順書です（skills/<名前>/SKILL.md）。エージェントは、依頼に当てはまるスキルだけを、必要なときに読みます。足し方は、チャットで頼む「スキル登録」、繰り返しから提案させる「スキル提案」、ファイルを置く方法の 3 通りです。どれも、手順書になるのは、人が中身を確かめてからです。

チャットで頼む（スキル登録）

入力欄の / から「スキル登録」を選び、どんな手順書にしたいかを書いて送ります。先頭に「名前:」を書くと、その名前になります（省くと、名前も考えます）。

weekly-sales: 毎週の売上を地域ごとにまとめる
今やった集計を、毎週使える手順書にして

2 つ目のように、そのチャットのやりとりを指して頼むこともできます。下書きが気に入らないときは、見送ってから、書き方を変えて頼み直します。

繰り返しから提案させるときは「スキル提案」です。入力欄の / から選ぶと、その場で依頼の記録を調べます。チャットを開いたときにも、記録がたまっていれば（5 件以上）裏で調べておき、次に開いたときに知らせます。

好きな内容を書いて足すときは、ファイルを置きます。skills/<名前>/SKILL.md の先頭に name（英小文字・数字・ハイフン）と description（どんなときに使うか）を書き、その下に手順を書きます。例は skills/python-testing/SKILL.md です。

定時実行と組み合わせられます。登録したスキルの名前を、定時実行の依頼文に書けば、決まった時刻に、その手順で作業させられます。

別の用途に使う

用途パックと、道具の扱い

用途ごとに違うものだけを、パックに書きます。packs/<名前>/ の pack.yaml（名前とあいさつ、使う道具、MCP サーバー）、SYSTEM.md（役割の文）、tools.py（Python の道具）です。守りの設定（config/security.yaml）は、どのパックにも共通です。

いまあるパックは 2 つです。data（データ分析。毎日使っているもの）と、見本の internal_api_example（社内の受注システムの見本を MCP で調べ、税込みの金額を Python の道具で出す）。社内の API は MCP でつなぎます。Python の道具は、計算のように毎回同じ答えにしたい処理に使います。

1 つのアプリは、1 つのパックで動きます。作業フォルダ・長期メモ・スキルは、アプリごとです。2 つの用途を同時に使うときは、アプリを 2 つ動かします。

手順は docs/tutorials/ にあります。パックの作り方、社内 API を MCP でつなぐ方法（見本で試せる）、Python の道具の書き方、確かめ方です。

src/data_agent/ の中

フォルダの関係

新しいファイルは、役割に合うフォルダに置きます。src/data_agent/ の直下には足しません（ADR-0028）。

各フォルダの説明もあります。どのフォルダにも、__init__.py の先頭に、中のファイルの役割を書いてあります。

agent.py・settings.py は動かしません。ファイルの場所をもとに、プロジェクトの場所を計算しているためです。役割の文（もとの prompts/）は、2026-11-17 に用途パック packs/data/ へ移しました（ADR-0032）。
