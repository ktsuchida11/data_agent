# ADR-0035: 変更の記録を git で残し、GitHub の非公開のリポジトリに置く

- **状態:** 採用（実装済み）。オーナーが決めた（2026-11-18。「gitを始めて、非公開のリポジトリの準備をお願いします」。置き場所は、選択肢から「個人のアカウント」を選んだ）
- **日付:** 2026-11-18
- **決定者:** プロジェクトオーナー
- **対象:** data_agent

## 状況

- 2026-11-18 まで、このフォルダは git で管理されていなかった。ADR-0034 の作業では 50 以上のファイルを変えたが、変える前と後を見比べることも、元に戻すこともできなかった。
- 公開の準備を確かめたとき（2026-11-18）、外に出してはいけないものは見つからなかった。テストに入っている鍵は、すべて偽物。`.env`、`logs/`、`workspace/`、`private/` は、記録から外す設定になっていた。
- オーナーの Mac では、git を始めると、git-secrets（AWS の鍵を記録に入れないための点検）が自動で入る設定になっている（`~/.git-templates`）。

## 決定

1. **git で管理するのは `LangChain/data_agent` のフォルダだけ。** 上の `t_claw` 全体は管理しない。ほかのアプリと記録を分けるため。枝の名前は `main`。
2. **GitHub の個人のアカウントに、非公開のリポジトリ `ktsuchida11/data_agent` を作る。** 料金はかからない（無料のプランでも、非公開のリポジトリを作れる）。見られるのはオーナーだけ。人を招くかどうかは、オーナーが決める。
3. **記録に入れないものは `.gitignore` に書く。**
   - 鍵: `.env`、`.env.*`、見本の認証局の秘密鍵（`examples/internal_api/ca-key/`、`private/example-ca/`）
   - 実行の記録: `logs/`
   - 作業の場所: `workspace/`、`.files/`（画面から上げたファイル）
   - 外に出さないもの: `private/*`（見本の `*.example.*` だけ残す）
   - 道具が作るもの: `.venv/`、各種のキャッシュ、`.DS_Store`、`.playwright-mcp/`、Claude Code の手元の設定（`.claude/settings.local.json`、`.claude/.cc-writes/`）
4. **長期メモ（`memories/`）とスキル（`skills/`）は、記録に入れる。** どちらも、アプリが書き換える場所（`compose.yaml` でコンテナに見せている）。承認したスキルや長期メモの追記は、git の差分として見える。記録する前に中身を確かめる。
5. **記録に付く名前とメールアドレスは、Mac の git の設定（オーナーが決めたもの）を使う。** こちらでは変えない。
6. **記録の前に、git-secrets の点検が走る。** オーナーの初期設定から、点検の仕組み（フック）を入れた。
7. **AI が作業するときも、記録（コミット）と GitHub への送信（プッシュ）は、オーナーに頼まれたときだけ行う。** 作業が終わったら、`git status` と `git diff` で変えたところを示す。

## 検討した案

| 案 | 内容 | 判断 |
|---|---|---|
| **A. git + GitHub の非公開（個人のアカウント）** | `ktsuchida11/data_agent` | **採用**。無料。Mac が壊れても記録が残る。オーナーが選んだ |
| B. git + GitHub の非公開（組織 `Zui-Tech-Platform`） | 組織の中に置く | 不採用。無料だが、組織の管理者やメンバーにも見える場合がある。オーナーが個人を選んだ |
| C. git だけ（Mac の中） | GitHub に置かない | 不採用。無料で、見比べと元に戻すことはできるが、Mac が壊れると記録も消える |
| D. 自前の git サーバー（Gitea など） | 手元か AWS に立てる | 今は不採用。無料だが、サーバーの運用と、記録の予備の保存を自分でする必要がある |

## 確かめたこと（2026-11-18）

- **記録に入れるファイル:** 192 個。公開の準備の確認で見た一覧と同じ（`.gitignore` に足したものは、もともと無かった）。
- **鍵の点検:** `git secrets --scan --cached` で、見つからなかった。テストの AWS の鍵は、AWS が公開している見本（`AKIAIOSFODNN7EXAMPLE`）で、git-secrets も許している。
- **ADR の書き方:** `uv run --offline pytest -q tests/test_adr_records.py` が通った。
- **GitHub:** リポジトリが非公開（`PRIVATE`）であることを、`gh repo view --json visibility` で確かめた。

## 分かっている制約

- **記録は 2026-11-18 から。** 最初の記録が、その日の状態になる。それより前の変更の流れは、ADR にだけ残っている。
- **CI（GitHub に送るたびにテストを流す仕組み）は、まだない。** GitHub Actions を使うなら、非公開のリポジトリは月 2,000 分まで無料（無料のプラン）。
- **会社の名前とメールアドレスが記録に入る。** `pyproject.toml` の作者の欄と、記録に付くメールアドレス。外に公開するときに見直す。
- **ライセンスのファイルは、まだない。** 非公開のあいだは要らない。外に公開するときに決める。
- **AI の作業用のサンドボックス（作業の制限）の中からは、git を始めることと GitHub へのログインができない。** フックを `.git/hooks` に書くことと、キーチェーン（GitHub のログイン情報）を読むことが止められているため。`git init` と `gh` は、サンドボックスの外で動かした。
