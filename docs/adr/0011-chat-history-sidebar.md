# ADR-0011: 過去のチャットの一覧と再開は、Chainlit 標準の履歴保存で実現する

- **状態:** 採用
- **日付:** 2026-11-13
- **決定者:** プロジェクトオーナー
- **対象:** data_agent

## 状況

- 会話を PostgreSQL に保存できるようになりましたが、画面から過去のチャットを開き直す手段がありませんでした（ADR-0010）。
- オーナーの希望は次の4つです。
  1. 画面の左側で、セッション（チャット）を選べる
  2. セッションごとに、会話の履歴を管理できる
  3. アーカイブできる
  4. グループにまとめられる
- Chainlit 2.12.0 の標準機能を、インストール済みのものから確認しました。

| 希望 | Chainlit の標準機能 |
|---|---|
| 左側でチャットを選ぶ | ある（「過去のチャット」の一覧。日付ごとに並び、名前で検索できる） |
| チャットごとの履歴の管理 | ある（開き直し、名前の変更、削除） |
| アーカイブ | ない |
| グループ分け | ない |

## 決定

- **1 と 2 は、Chainlit 標準の履歴保存（データ層）で実現します。** 実装済みです。
- **保存先は、会話の保存と同じデータベース `coding_agent` です**（ADR-0010）。`DB_HOST` を設定したときだけ有効になります。
- **Chainlit のチャットの ID を、エージェントの会話の ID としてそのまま使います。** 開き直したチャットが、同じ会話の続きになります。
- **画面でチャットを削除したら、エージェント側に保存した会話も消します。**
- **3 と 4 は、Chainlit の標準にないので独自に作ります。** 今の画面のまま、チャットの中のコマンドで補う方式（下の選択肢 A）にしました。実装済みです。

## 履歴保存の実装の選び方

Chainlit には PostgreSQL 用の実装が2つ入っています。

| | A. ChainlitDataLayer（採用） | B. SQLAlchemyDataLayer |
|---|---|---|
| **一覧の取得** | チャットの表だけを、必要な件数だけ読む | 一覧を出すたびに、全チャットの全メッセージを読み込む |
| **保存の失敗** | エラーになる | 警告を出すだけで続行する。テーブルにない項目があると、気づかないまま保存されない |
| **テーブル定義** | Chainlit の配布物にもドキュメントにも載っていない | ドキュメントに載っている |
| **追加で要るもの** | asyncpg | SQLAlchemy と asyncpg |

A を選びました。メッセージが大きくなりやすいコーディング用途では、一覧のたびに全メッセージを読む B は重くなるためです。

A のテーブル定義は、`chat_history.py` に持たせました。Chainlit 2.12.0 のコードが読み書きする列に合わせてあります。**Chainlit を上げるときは、そのコードの SQL と見比べる必要があります。**

## 標準の実装に手を入れた点

- **接続数の上限:** 標準は接続を常に10本開きます。共有している PostgreSQL の接続数を使いすぎないよう、上限を `DB_POOL_MAX`（既定は 5）にしました。
- **削除の連動:** チャットを削除したときに、エージェント側の会話（チェックポイント）も消すようにしました。
- **承認待ちの再開:** 承認待ちのまま閉じられたチャットを開き直したときは、もう一度承認を求めます。

## 確かめたこと（2026-11-13）

使い捨ての PostgreSQL（`postgres:17`）と、決まった返事を返す偽のモデルを使い、画面と同じ通信（ログイン、WebSocket、API）で確かめました。手元の Langfuse の PostgreSQL と API キーは使っていません。

**確認できたこと**
- メッセージを送ると、チャットが一覧に出る。名前は最初のメッセージになる。
- 人とアシスタントの発言が保存される。
- アプリを再起動しても、チャットが一覧に残る。
- 一覧のチャットを開き直せる。続けて送ると、返事が「2通目」になる（会話が引き継がれている）。
- 名前を変更できる。
- 削除すると、一覧から消える。データベースからも、画面の履歴とエージェント側の会話の両方が消える。
- `DB_HOST` を設定しない場合は、これまでどおり動く（一覧は出ない）。
- 単体テスト 18 件が通る。

**確認していないこと**
- ブラウザの画面での見た目と操作。通信のやりとりで確かめたので、左側の一覧が実際にどう見えるかは見ていません。
- 本物のモデルでのやりとり。
- ツールを呼び出したときの途中経過が保存されること。偽のモデルはツールを呼ばないためです。
- 承認待ちのまま閉じたチャットを開き直したときの動き。
- 利用者が複数いるときに、ほかの人のチャットが見えないこと。Chainlit が持ち主を確認する作りですが、利用者が1人の設定なので試していません。

## 分かっている制約

- **保存される内容:** メッセージに加えて、ツールの入力と出力（それぞれ先頭 4,000 文字まで）も保存される作りです。ファイルの中身が含まれることがあります。いつまで残すかは未決です（ADR-0010）。
- **終了時のログ:** コンテナを止めると、ログに "Application shutdown failed" が出ます。Chainlit が一時フォルダ `.files` を消そうとして、書き込み禁止の設定に当たるためです。後片付けはその前に済んでいて、終了コードも 0 なので、動作への影響はありません。
- **検索の対象:** 検索できるのはチャットの名前とグループ名です。メッセージの中身は検索されません。
- **グループの見出し:** 一覧は日付ごとの並びのままで、グループごとの見出しは出ません。グループ名は名前の先頭に付くだけです。
- **最初のメッセージがコマンドのチャット:** チャットの名前は最初のメッセージから付くので、コマンドに書いた文字（グループ名など）が名前になります。

## アーカイブとグループ分けの選択肢

| | A. 今の画面のまま、チャットの中の操作で補う（採用） | B. 左側の一覧を作り替える | C. 画面を Chainlit 以外で作り直す |
|---|---|---|---|
| **アーカイブ** | チャットの中のボタンやコマンドで、そのチャットを一覧から隠す。隠したものは別のコマンドで一覧にして戻せる | 一覧にアーカイブの操作と、アーカイブ済みの一覧を足す | 自由に作れる |
| **グループ** | チャットにグループ名を付け、名前の先頭に出す（例: `[案件A] 設計の相談`）。検索で絞り込める。見出しは出ない | グループごとの見出しや、ドラッグでの移動を作れる | 自由に作れる |
| **作る量** | 小 | 大 | 最大（承認ボタンや途中経過の表示も作り直す） |
| **Chainlit を上げたときの影響** | 小 | 大（画面の作りに依存する） | なし |

オーナーが A を選びました（2026-11-13）。作る量が小さく、使ってみてから B に進むかを決められます。アーカイブとグループの情報はデータベースに持つので、A で作ったデータは B でもそのまま使えます。

## アーカイブとグループ分けの仕組み（選択肢 A）

入力欄で `/` を打つと選べるコマンドで操作します。過去のチャットを保存しているときだけ使えます。

| コマンド | 動き |
|---|---|
| アーカイブ | いま開いているチャットを、左の一覧から隠す |
| アーカイブ一覧 | 隠したチャットを表示する。ボタンを押すと、一覧に戻る |
| グループ | いま開いているチャットにグループ名を付ける（コマンドを選び、グループ名を書いて送る） |
| グループ解除 | いま開いているチャットをグループから外す |

- **データの持ち方:** `Thread` の表に、このアプリ独自の列（`archivedAt`、`groupName`）を足しました。Chainlit も読み書きする付加情報（`metadata`）には入れていません。開いたままの画面が持つ古い値で、上書きされる恐れがあるためです。
- **グループ名の見せ方:** 一覧を返すときに、名前の先頭へ `[グループ名]` を付けます。保存している名前には付けません。画面で名前を変更すると `[グループ名]` 付きの名前が送られてくるので、保存する前に外します。
- **検索:** チャットの名前に加えて、グループ名でも絞り込めます。
- **エージェントとの関係:** コマンドのメッセージは、エージェント（モデル）に渡しません。画面の履歴には残ります。
- **本人の確認:** アーカイブとグループ分けの更新は、本人のチャットだけを対象にします。ボタンの中身は利用者の側から送られてくるので、チャットの ID の形式と持ち主を確かめます。
- **最初のメッセージがコマンドの場合:** Chainlit はチャットの登録を裏で並行して行うので、登録が終わるまで最大3秒、再試行します。

**確認できたこと（2026-11-13）**

使い捨ての PostgreSQL と偽のモデルで、画面と同じ通信を使って確かめました。

- グループに入れると、一覧で名前の先頭にグループ名が付く。グループ名で検索すると絞り込める。
- 画面と同じ方法で名前を変更しても、グループ名が二重に付かない。
- アーカイブすると一覧から消え、「アーカイブ一覧」に出る。ボタンで一覧に戻せる。
- 存在しないチャットの ID を入れたボタンでは、何も変わらない。
- ほかの利用者のチャットは、アーカイブもグループ分けもできず、一覧にも出ない（データベースに別の利用者のチャットを作って確認）。
- コマンドのメッセージは、エージェントに渡らない（コマンドのあとの返事が「2通目」になることで確認）。
- チャットの最初のメッセージがコマンドでも動く。
- 前回確認した一覧・再開・名前の変更・削除が、引き続き動く。
- 単体テスト 20 件が通る。

**確認していないこと**

- ブラウザの画面での見た目と操作。次の点は、実際の画面で見る必要があります。
  - `/` を打ったときのコマンドの出方と、日本語のコマンド名での絞り込み。
  - 「アーカイブ」「アーカイブ一覧」「グループ解除」を、本文を空のまま送れるか。送れない場合は、何か1文字書いて送ります。
  - 「アーカイブ一覧」の「開く」のリンクで、そのチャットが開くか。
  - アーカイブしたあと、左の一覧がいつ更新されるか。
