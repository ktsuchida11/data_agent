# ADR-0003: セッションは1チャット単位とし、またいで残す情報はメモリ・スキル・作業フォルダに置く

- **状態:** 一部置き換え済み（→ ADR-0010）。会話の保存先は PostgreSQL にもできるようになった
- **日付:** 2026-11-13（設計はフェーズ1の時点のもの）
- **決定者:** プロジェクトオーナー

## 状況

「セッションの考え方がよく分からない」「メモリの機能はあるのか」という質問が出たので、現行の状態の持ち方を記録します。

## 決定（現行の設計）

- **1セッション = 1つのチャットです。** ブラウザでチャットを開くたびに新しい ID（`thread_id`）を発行します。
- **セッション内の状態は、チェックポインタが `thread_id` ごとに保持します。** 対象は会話履歴、TODO、読み込み済みのメモリとスキル一覧です。保存先はメモリ上（`InMemorySaver`）です。
- **セッションをまたいで残したいことは、次の3か所に置きます。**
  - `workspace/`: エージェントが作業するファイル
  - `memories/AGENTS.md`: 長期メモ。セッションの最初に読み込まれます。エージェントが書き込むときは承認が必要です
  - `skills/`: 手順書。セッションの最初に名前と説明だけが読み込まれ、本文は必要になったときに読まれます。エージェントからは書き込めません

| | 同じセッション内 | 別のセッション | アプリ再起動後 |
|---|---|---|---|
| 会話履歴・TODO | 残る | 引き継がれない | 消える |
| `workspace/` のファイル | 残る | 残る | 残る |
| `memories/AGENTS.md`・`skills/` | 残る | 残る | 残る |

## 影響

- アプリを再起動すると会話は消えます。過去のチャットを開き直す機能もありません（Chainlit のデータ層を設定していないため）。
- メモリとスキルの変更は、次のセッションから反映されます。どちらもセッションの最初に1回しか読み込まれないためです。
- 操作の記録がどこにも残りません。繰り返し操作の検出（ADR-0007）には、記録の仕組みを先に作る必要があります。

## 追記（2026-11-13）

`DB_HOST` を設定すると、会話を PostgreSQL に保存するようになりました（ADR-0010）。設定しなければ、上の説明のとおりメモリ上に保存します。
PostgreSQL に保存しているときは、左側の一覧から過去のチャットを開き直せます（ADR-0011）。
チャットの ID は Chainlit のものをそのまま使うようになり、開き直すと同じ会話の続きになります。

## 未決事項

- 会話を保存して再開できるようにするか。ADR-0010 と ADR-0011 で対応済みです。ローカル版では、チェックポインタを SQLite などに変え、Chainlit のデータ層を設定すれば実現できます。Managed Deep Agents ではスレッドが保存されます（ADR-0001）。
