# ADR-0017: データベース（PostgreSQL）のデータは、読み取り専用のツールで取り、CSV にして受け渡す

- **状態:** 採用（実装済み）。データベースの種類を PostgreSQL にすることは、オーナーが決めた（2026-11-14）。ツールの形（結果を CSV に保存すること、守りの重ね方、承認を既定では求めないこと）は、提案どおりに実装した。オーナーが、本物のモデルと練習用のデータで動かし、思ったとおりの内容が返ることを確かめた（2026-11-14）。ツールの形でよい、という明示の返事はまだない。読みに行くデータベースは、手元の PostgreSQL（Langfuse と同じコンテナ）に置くことに決まった（2026-11-14）。個人情報の列の扱いは、ADR-0019 で決めた。→ 2026-11-18: 管理者のほか、すべての表を読める組み込みのロール（pg_read_all_data など）に入ったロールも断るようにした。列ごとに読めなくした設定が効かないため（ADR-0034）
- **日付:** 2026-11-14
- **決定者:** プロジェクトオーナー
- **対象:** data_agent

## 状況

- コード実行の主な用途は、データベースから取ったデータの可視化と、表・資料の作成です（ADR-0016）。
- コードを実行するコンテナは、データベースにつながりません（ADR-0016）。データを取る役は、アプリの側に要ります。
- 読みに行くデータベースには、業務のデータが入ります。会話の保存先（ADR-0010）とは別のものです。エージェントに書き換えさせてはいけません。

## 決定

- **エージェントに、データベースを読むツールを2つ持たせます。** 表と列を調べる `list_database_tables` と、SQL を1つ実行する `query_database` です。
- **読み取り専用にします。** 守りは1つに頼らず、重ねます（下の「守り」）。
- **結果は CSV にして作業フォルダに保存し、モデルには先頭の 30 行だけを見せます。** 全体を使う集計やグラフは、その CSV を `run_python` に渡して行います。
- **接続先は `.env` の `DATA_DB_*` で決めます。** 設定しなければ、ツールは付きません。
- **問い合わせのたびの承認は、既定では求めません。** 設定（`database.require_approval`）で、承認制に変えられます。

## 仕組み

| 段階 | 内容 |
|---|---|
| **表を調べる** | モデルが `list_database_tables` を呼ぶ。読める表の名前、行数の見積もり、列の名前・型・説明（コメント）が返る |
| **問い合わせ** | モデルが `query_database` に、SQL と、結果に付ける名前を渡す |
| **実行** | アプリが、読み取り専用のロールでつなぎ、読み取り専用のトランザクションの中で実行する。既定は 30 秒まで |
| **受け取り** | 行を 1,000 行ずつ受け取る。10,000 行か 10 MB に達したら、そこで打ち切って、その旨を伝える |
| **保存** | 作業フォルダの `outputs/<日時>-<乱数>/<名前>.csv` に保存する。秘密情報やカード番号らしい値は、マスクしてから保存する |
| **モデルへの返事** | 行数、列の名前と型、保存先、先頭の 30 行 |
| **続きの処理** | モデルが、保存先のパスを `run_python` の `input_files` に渡して、集計やグラフを行う |

| ファイル | 役割 |
|---|---|
| `src/data_agent/tools/database.py` | 2つのツール。接続、読み取り専用の実行、CSV への保存 |
| `src/data_agent/tools/outputs.py` | 作業フォルダに保存するときの共通の処理（権限の確認、保存先の名前）。コードの実行と共用 |
| `scripts/setup_data_db.sh` | 読み取り専用のロールを作り、接続情報を `.env` に追記する（手元の PostgreSQL のコンテナ向け） |
| `scripts/sample_data.sql` | 練習用のデータ（架空の商品・顧客・注文） |
| `config/security.yaml` の `database` | 時間、行数、大きさ、承認の要否 |
| `compose.yaml` | コンテナの中での接続先（`DATA_DB_DOCKER_HOST`）への読み替え |

## 守り

| 守り | 内容 |
|---|---|
| **読み取り専用のロール** | 表を読むことだけを許したロールでつなぐ。これが本当の守りで、下の守りがすべて破られても、書き込めない |
| **管理者は断る** | 管理者（スーパーユーザー）のロールでつないだときは、問い合わせを受け付けない。管理者は、読み取り専用のトランザクションの中でも、サーバーのファイルを読むなどの操作ができるため |
| **読み取り専用の接続** | 接続そのものを読み取り専用にして、読み取り専用のトランザクションの中で実行する |
| **カーソルとして実行する** | SQL は、データベースの側のカーソルの中身として渡す。カーソルにできるのは SELECT の類だけで、複数の文をまとめて送っても、データベースが受け付けない |
| **先頭の言葉を確かめる** | SELECT・WITH・VALUES・TABLE で始まらない文は、データベースに送らない |
| **上限** | 時間（30 秒）、行数（10,000 行）、大きさ（10 MB）。超えたら止める |
| **ガードレール** | モデルに返す文章は、ほかのツールの結果と同じくマスクされる。保存する CSV も、マスクしてから保存する |
| **監査ログ** | 問い合わせのたびに、行数・列数・かかった時間・打ち切りの有無を記録する。SQL の文面と、値は記録しない |
| **持たせる相手** | 調べるだけのサブエージェント（`explorer`）には持たせない |
| **実行する場所** | 接続するのはアプリだけ。コードを実行するコンテナからは、データベースに届かない |

## 検討した選択肢

| | A. 独自のツール（採用） | B. LangChain の SQL 用のツール群 | C. コードを実行するコンテナからつなぐ |
|---|---|---|---|
| **追加の料金** | なし | なし | なし |
| **追加のライブラリ** | なし（psycopg は、会話の保存で使っている） | 要る | 実行用のコンテナに要る |
| **結果の渡し方** | CSV に保存し、モデルには先頭だけ | そのままモデルに返す | コードが直接読む |
| **読み取り専用の守り** | ツールの側でも重ねる | ロールの権限に任せる | ロールの権限に任せる |
| **実行用のコンテナの隔離** | 変わらない | 変わらない | 崩れる（外へ出る経路と、接続情報を持たせることになる） |

- B は、作る量がいちばん少ない案です。結果をそのままモデルに返すので、行数が多いと料金がかさみ、グラフにするときにデータをもう一度渡す必要があります。
- C は、ADR-0016 の「実行する環境は、データベースにつながない」を崩すので、選びませんでした。

## 確かめたこと（2026-11-14）

偽のモデルと、使い捨ての PostgreSQL（練習用のデータ）を使って確かめました。

**ツールの中身（35 項目。`tests/e2e/check_database.py direct`）**
- 表の一覧に、説明と行数の見積もりが出る。集計の結果が返り、CSV に保存される。
- 日付、数値、JSON、配列、空の値、バイナリを CSV にできる。0 行でも列の名前が分かる。
- 行数、大きさ、時間の上限で止まる。止まったあとも、次の問い合わせができる。
- DELETE・INSERT・DROP・TRUNCATE は送られない。複数の文は、データベースが受け付けない。
- 読み取りの形をした書き込み（WITH の中の DELETE、SELECT INTO、番号を進める関数、行のロック）は、データベースが断る。
- ツールを通さずにつないでも、ロールそのものが書き込めない。注文の件数は、最後まで変わらなかった。
- 管理者のロールでは、問い合わせを受け付けない。つながらないときのメッセージに、パスワードは出ない。

**アプリとつないだ状態（16 項目と、承認制の 5 項目。`tests/e2e/check_database.py chat`・`approval`）**
- 問い合わせの結果がモデルに届き、CSV が作業フォルダに保存される。その CSV を `run_python` に渡して集計できる。
- 結果に出たキーらしい文字列は、モデルに渡る前にも、保存した CSV でも、マスクされる。
- 汎用のサブエージェントは問い合わせができ、調べるだけのサブエージェントはできない。
- 承認制にすると、拒否したときは実行されず、承認したときだけ実行される。

**準備用のスクリプト（`scripts/setup_data_db.sh`）**
- 練習用のデータベースを作れる。すでにあるデータベースを指定できる。表を足したあとに、もう一度実行すると、読めるようになる。
- 作ったロールは、指定したデータベースの表を読めて、書けない。ほかのデータベースの表は読めない（接続そのものは、PostgreSQL の既定の設定ではできる。ADR-0019 の「分かっている制約」）。
- `postgres`（Langfuse のデータベース）と、英数字と `_` 以外を含む名前は、受け付けない。

単体テストは 19 件を足しました（`tests/test_database.py`）。

**オーナーが本物のモデルで確かめたこと（2026-11-14）**
- 「どんな表があるか見せて」と「地域ごとの売上を月別に集計して、折れ線グラフにして」を依頼し、どちらも思ったとおりの内容が返った、と報告がありました。使ったモデルは聞いていません。
- 作業フォルダの `outputs/` に、そのときのファイルが残っています。月と地域ごとの集計（110 行の CSV）、モデルが自分から行ったデータの点検（件数や欠けた値を数える問い合わせ）、折れ線グラフの画像です。グラフは、題名・軸・凡例の日本語が正しく表示されていました。
- 動いているアプリのコンテナで、接続先を確かめました。ホスト名は `postgres`、データベースは `coding_agent_sample`、ロールは `coding_agent_reader` です。準備用のスクリプトが手元の Langfuse の PostgreSQL で動き、`compose.yaml` の接続先の読み替えも働いています。
- グラフの数値が、データベースの中身と合っているかの突き合わせは、していません。

**確認していないこと**
- オーナーのデータベース（練習用ではないもの）での動作。表や列の数が多いときに、モデルが正しい SQL を書けるか。
- AWS の RDS への接続（`DATA_DB_SSLMODE=require`）。

## 分かっている制約

- **問い合わせの結果の先頭 30 行は、モデル（Anthropic の API）に送られます。** 会話の履歴にも残ります。個人情報の列は、データベースの側で読めなくします（ADR-0019）。
- **氏名や住所のように、形が決まっていない情報は、ガードレールでは見つけられません。** 読めなくしていない列に入っていれば、CSV にもモデルにも、そのまま渡ります。メールアドレスと電話番号は、マスクされます（ADR-0019）。
- **対応しているのは PostgreSQL だけです。**
- **1回の問い合わせで受け取れるのは、10,000 行・10 MB までです。** 大きな表は、SQL の側で集計するか、条件で絞ります。
- **EXPLAIN と SHOW は使えません。** カーソルにできる文（SELECT の類）だけを受け付けるためです。
- **管理者かどうかの判定は、スーパーユーザーかどうかだけです。** AWS の RDS の管理ユーザーはスーパーユーザーではないので、判定を通ります。書き込みは、読み取り専用のトランザクションが止めますが、必ず専用のロールを作ってください。
- **準備用のスクリプトが権限を付けるのは、実行した時点である表だけです。** 表を足したら、もう一度実行します。対象のスキーマは `public` です（`DATA_SCHEMAS` で変えられます）。
- **接続は、問い合わせのたびに開いて閉じます。** 問い合わせが多い使い方では、遅く感じるかもしれません。
- **結果の CSV は、チャットにはダウンロード用のファイルとして出ません。** 作業フォルダの `outputs/` に残ります。受け取りたいときは、エージェントに Excel などにしてもらいます。`outputs/` のファイルは、自動では消えません。

## 見直す条件

- PostgreSQL 以外のデータベースを読むことになったとき。
- 個人情報を含む表を読ませることになったとき（列を絞ったビューを用意する、マスクする種類を増やす、などを決める）。
- 複数人で使うようになり、利用者ごとに読める表を分けたくなったとき。
