# ADR-0034: 決めたことの記録を既定にし、書き方の点検・整形・セキュリティの点検を、変更のたびに通す

- **状態:** 採用（実装済み）。オーナーが決めた（2026-11-18。「ADRのように仕様や機能がどのように決まったかを残すようにする指示をデフォルトで設定してください、Linter・Formater、リファクタリングとセキュリティのチェックをおこない、なるべくコードの内容がわかりやすくメンテナスしやすい状態にしたいです」）
- **日付:** 2026-11-18
- **決定者:** プロジェクトオーナー
- **対象:** data_agent

## 状況

- オーナーは、このプロジェクトをほかの AI に引き継ぐ準備をしている（2026-11-18。「これを他のAIに引き継ぐための資料は揃っていますか？」）。
- 決めたことは ADR に残してきたが、残すかどうかは、その場の判断と、オーナーの依頼に頼っていた。引き継いだ AI が、同じように残すとは限らない。
- 書き方の点検（Linter）と整形（Formatter）の道具は、入っていなかった（`pyproject.toml` の開発用の依存は pytest だけ）。書き方は、人と AI の手で揃えていた。
- 分岐の多い関数（画面の返事の表示、検索の前の判定など）が、いくつかあった。
- セキュリティは、OWASP LLM Top 10 の点検（ADR-0020）と、依存の脆弱性の点検（ADR-0024）で見てきたが、コードの書き方の点検（bandit のようなもの）はしていなかった。
- このフォルダは git で管理されていない。変更の前後を見比べる手段がないので、変える前に写しを取った。→ 2026-11-18 に git を始めた（ADR-0035）。

## 決定

1. **決めたことの記録を、既定の作業にする。**
   - **決まり:** AGENTS.md に「決めたことを残す（既定）」の節を置いた。残すとき（機能を足す・変える・やめる、守りの決まり、依存、外のサービス、データの持ち方、オーナーが選んだこと）、残し方、書いたあとの確かめを書いた。頼まれなくても行う。
   - **読ませ方:** AGENTS.md は、多くの AI のコーディングエージェントが読む。Claude Code 用に、同じものを読ませる `CLAUDE.md`（`@AGENTS.md` の 1 行）を置いた。
   - **ひな形:** `docs/adr/template.md`。
   - **確かめ:** `tests/test_adr_records.py` が、番号の連番、ファイル名、1 行目、状態・日付・決定者、「状況」と「決定」の節、AGENTS.md と `docs/adr/README.md` の一覧の漏れを確かめる（ふだんの単体テストに入っている）。
2. **書き方の点検と整形は、Ruff で行う**（無料。手元で動く。開発用の依存に入れ、アプリのイメージには入らない）。
   - **整形:** `uv run ruff format .`。行の幅は 130（いまのコードに合わせた。変わる行がいちばん少ない）。
   - **点検:** `uv run ruff check .`。基本の誤り、import の並び、誤りのもとになりやすい書き方、古い書き方、短く書ける所、複雑すぎる関数（分岐 10 まで）、セキュリティ（bandit と同じ点検）、Ruff 独自の点検。
   - **外した点検:** 日本語の全角の記号（わざと使っている）、長い行（整形に任せ、日本語の文は折らない）、入れ子の for を内包表記にする提案（読みにくくなる）。テストでは、`assert`、偽の鍵、手元のサーバーへの http、テスト用の SQL、偽のモデルの共有の入れ物を外す。
   - **誤検知:** `# noqa: <番号>  理由` と、理由を添えて止める。理由のない `noqa` は書かない。
3. **リファクタリングは、動きを変えずに、分岐の多い関数を役割ごとに分ける。** 分けた関数には、何をするかを docstring に書く。変える前後で、単体テストと画面の回帰確認を通す。
4. **セキュリティの点検は、次の 4 つで行う。**
   - コードの書き方（Ruff の `S`。変更のたびに）
   - 依存の既知の脆弱性（`scripts/audit_deps.sh`。毎日と、依存を変えたとき。ADR-0024）
   - 鍵の形をした文字列が、ファイルに残っていないか（今回は手で調べた）
   - コードを読む点検（今回は、書いた人の見方に寄らないよう、別の AI に読ませた）
5. **コードを変えたら、`ruff format`・`ruff check`・単体テストを通す**（AGENTS.md の「作業の決まり」、README の「コードを変えたときの確認」）。

## 検討した案

| 案 | 内容 | 判断 |
|---|---|---|
| **A. Ruff だけ** | 点検と整形を 1 つの道具で。bandit と同じ点検も入っている | **採用**。無料、速い、設定が `pyproject.toml` の 1 か所 |
| B. flake8・black・isort・bandit | 同じことを 4 つの道具で | 不採用。道具と設定が 4 つになる。点検の中身は A とほぼ同じ |
| C. 型の点検（mypy・pyright）も入れる | 型の食い違いを見つける | いまは見送り。型を書いていない所が多く、最初の直しが大きい。引き継いだあと、少しずつ入れるかを決める |
| D. 記録（commit）の前に自動で通す（pre-commit） | 通らなければ記録できない | いまは見送り。git がない。git を入れたら考える（→ 2026-11-18 に git を始めた。ADR-0035。まだ入れていない） |
| E. SonarQube・Semgrep など | 大きな点検の仕組み | 不採用。SonarQube は自前で動かすと重い。いまの大きさでは、A と単体テストで足りる |

## 確かめたこと（2026-11-18）

- **決めたことの記録:** いまある 33 件の ADR が、すべて書き方の確かめを通った（直さずに）。
- **点検:** 最初は 4,195 件。日本語の全角の記号（3,189 件）と、テストの `assert`（758 件）を外したあと、71 件。
  - **直した 2 つ（本当の心配）:**
    - スキルの候補探しを裏で動かすとき、タスクの参照を持っていなかった（`ui/skill_commands.py`）。Python は、参照のないタスクを終わる前に片付けることがある。参照を持つようにした。
    - 監査ログの文脈の既定の値が、書き換えられる辞書だった（`safety/audit.py`）。いまの使い方では書き換えていないが、書き換えられない形にした。
  - **誤検知（理由を添えて止めた）:** 固定の文字列を鍵と見なしたもの（検出の種類の名前、区切りの記号、攻撃の題材のファイルの場所）、値を `$1` で渡している SQL（会話の一覧）、コンテナの中の `0.0.0.0`、使い終わった一時の場所を空にする処理。
  - **書き方の直し:** import の並び、不要な import、`contextlib.suppress`、`next(...)`、正規表現の書き方など。
- **整形:** 54 ファイルを整形した（変わった行は、ほとんどが長い式の折り返し）。
- **リファクタリング（分岐が 10 を超えた 10 の関数）:**
  - `safety/search_screen.py` の `screen`（15）と `local_texts`（13）: 見張る言葉・番号やコード・表の値・長い文の 4 つの判定と、手元のデータを集める処理を、それぞれの関数に分けた。
  - `safety/grounding.py` の `derived`（12）: 列の計算と、行を分けた計算を分けた。
  - `ui/app.py` の `_run`（16）: 返事の吹き出し（`_Bubble`）、流す文字の選び方、ツールの表示の開け閉めを分けた。
  - `tools/web_search.py` の `run`（11）: 断る理由、モデルを呼ぶ、返す文、に分けた。
  - `tools/registry.py` の `agent_tool`（11）: エラーを包む部分を分けた。
  - `evals/common.py` の `measure`（11）、`evals/factcheck/runner.py` の `selftest`（11）、`tests/e2e/fake_app.py` の 2 つ（19、15。言葉と操作の対応を表にした）。
- **単体テスト:** 580 件すべて通った（記録の確かめの 37 件を足した）。
- **点検の自己テスト（Docker の中、偽のモデル）:** `evals.redteam --selftest` と `evals.factcheck --selftest` は、どちらも通った。数も前と同じ（モデルが従っても止まるもの 13/21）。
- **依存の脆弱性（`scripts/audit_deps.sh`）:** アプリも、コードを実行する環境も、見つからなかった（Ruff を足したあと。`logs/audit/20261118-074159.txt`）。
- **鍵の形をした文字列:** 本物らしいものは、なかった（見つかったのは、テストの偽の鍵と、AWS が公開している例の鍵だけ）。`.gitignore` に、`.env.*`、点検の作業場所（`.pytest_cache/`、`.ruff_cache/`）、`private/` の中身（見本 `*.example.*` を除く）を足した。

### 結果

- **画面の回帰確認（`bash tests/e2e/regress.sh`）:** リファクタリングと整形のあと、18 種類・390 項目がすべて通った（`logs/e2e/20261118-074144`）。動きは変わっていない。
- **別の AI によるコードの点検（書いた人の見方に寄らないよう、結論を渡さずに読ませた）:** 10 件の指摘。1 件ずつ、コードを動かして確かめてから扱いを決めた。
  - **直した 6 件:**
    - **Langfuse に送る記録のマスクの穴（中〜高）:** Langfuse は、記録を JSON にするときに日本語を `\uXXXX` に書き換える。そのため「鍵はsk-…」「電話03-…」のように、日本語のすぐ後に書いた鍵と電話番号を見逃していた（手元で再現した）。ツールの結果（`ToolMessage`）も、中身を見ずにそのまま渡していた。JSON を読み戻してマスクし、メッセージの中身も見るようにした（`storage/tracing.py`。テスト 2 件）。
    - **実行のあとに残るプロセス（中）:** 残ったプロセスを止める処理が 1 回だけだったので、止めている間に作られたプロセス（二重の fork）が残り、次の実行（別のチャットや定時実行）をのぞける恐れがあった。なくなるまで繰り返し、止めきれなければサーバーを止める（`sandbox/server.py`）。
    - **MCP の引数の説明（低〜中）:** サーバーが返す引数の説明は、調べずにモデルに渡していた（ツールの説明は調べていた）。伏せて 300 文字で切る（`tools/mcp.py`。テスト 1 件）。
    - **データベースのロール（低）:** 管理者だけを断っていた。すべての表を読める組み込みのロール（`pg_read_all_data` など）に入ったロールも断る（`tools/database.py`。本物の PostgreSQL での確認 1 件を足した）。
    - **過去のチャットに残る入力（低）:** 利用者が書いた鍵などは、保存を 1 秒待ってから置き換えていたので、保存が遅いと残ることがあった。保存の手前でもマスクする（`storage/chat_history.py`）。
    - **作ったファイルの名前（低）:** 名前の `` ` `` や改行で、画面の説明を書き足せた。`approvals.inline()` を通す（`ui/app.py`）。
  - **再現しなかった 1 件:** 外とつながらないネットワークから、名前（DNS）が引けるか。引けなかった（使い捨てのネットワークで確かめた）。
  - **オーナーの判断を待つ 1 件（中）:** コードを実行する環境から、アプリの画面（ログイン）に届く。注入されたコードが、パスワードを総当たりで試せる。下の「次にやること」。
  - **分かっている制約として残した 2 件:** 下の「分かっている制約」。
- **直したあと（2026-11-18）:** 単体テスト 584 件、`ruff check`・`ruff format --check` が通った。画面の回帰確認は、コードを実行する環境の新しいイメージ（`data-agent-sandbox:check`）で、18 種類・391 項目がすべて通った（`logs/e2e/20261118-080036`。ロールの確認を 1 項目足した）。点検の自己テストも、前と同じ数で通った。

## 分かっている制約

- **マスクは、形を見て伏せるだけ（できる限りの守り）。** コードの実行や SQL で、値の形を変えて（base64 にする、間に空白を入れるなど）出されると、見逃す。画像や PDF の中身も見ない。外に出る経路の守り（確認、送る前の確かめ、コードを実行する環境にネットワークがないこと）と重ねて守る（ADR-0012、ADR-0019）。
- **返事は、流している途中はマスクする前の文字が画面に出る。** 確定するときにマスクし、保存されるのはマスクしたもの（`ui/app.py` の `_send_answer`）。
- **型の点検は、まだ入れていない**（案 C）。
- **点検を自動で通す仕組み（pre-commit や CI）は、まだない。** いまは、AGENTS.md の決まりと、単体テストの中の記録の確かめに頼る。git を入れたら、記録の前に自動で通すことを考える。
- **Ruff のセキュリティの点検は、書き方の形を見るだけ。** 権限や、データの流れの穴は見つけられない。それは、ADR-0020 の点検と、コードを読む点検で見る。

## 次にやること

- [ ] **コードを実行する環境から、アプリの画面に届く点**をどうするかを、オーナーが決める。案は 2 つで、どちらも料金はかからない。
  - (1) ログインの失敗が続いたら、しばらく受け付けない（小さな変更）
  - (2) コードを実行する環境を、アプリの画面と別のネットワークにする（構成の変更。ADR-0016）
- [ ] 直したコードを、動いているアプリに入れる（オーナーが `docker compose up --build -d`。コードを実行する環境のイメージも作り直される）
- [ ] git を入れるかを、オーナーが決める（入れたら、記録の前に `ruff` とテストを自動で通す）
- [ ] 型の点検（mypy か pyright）を入れるかを決める
