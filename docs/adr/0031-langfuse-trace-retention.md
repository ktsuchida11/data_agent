# ADR-0031: Langfuse に送った記録は、決めた日数（既定は 90 日）が過ぎたら、アプリが毎日消す

- **状態:** 採用（実装済み）。本物の Langfuse でも動いた（2026-11-17。下の「次にやること」）。オーナーが決めた（2026-11-16。「Langfuse に残す期間は選択できるようにしておいてください、とりあえず 90 日」）。ADR-0015 の「残す期間を決める」への答え
- **日付:** 2026-11-16
- **決定者:** プロジェクトオーナー
- **対象:** data_agent

## 状況

- モデルとのやりとりとツールの呼び出しを、Langfuse に送っている（ADR-0015）。送る前にマスクはしているが、会話の中身（読んだファイルの内容、データベースの結果など）が残る。
- **いつまで残すかは決めていなかった。** 自分で動かす Langfuse は、何もしなければ記録を消さない。
- **Langfuse に元からある「残す期間」の設定（Data Retention）は、自分で動かす場合は、有料の Enterprise 版だけで使える。** プロジェクトの設定画面の項目も、起動のときに決める環境変数（`LANGFUSE_INIT_PROJECT_RETENTION`）も、同じ扱い。
- 同じ Langfuse を、brew_app と studyops も使っている（プロジェクトは別）。
- オーナーは、料金のかからない、自前の構成を好む。

## 決定

1. **残す日数は、`config/security.yaml` の `tracing.retention_days` で決める。既定は 90 日。** 0 にすると消さない。変えたら、作り直す（`docker compose up --build`）。
2. **アプリが 1 日に 1 回、その日数より古い記録を、Langfuse の公開 API で消す**（`storage/trace_retention.py`）。
   - 起動してから 1 分後に 1 回目、そのあとは 24 時間ごと。Langfuse につながらなかったときは、1 時間後にやり直す。
   - Langfuse に記録を送っているとき（鍵が 2 つとも設定されているとき）だけ動く。
   - 記録を消すと、Langfuse は、その中のモデルの呼び出しや評価も、まとめて消す（Langfuse の裏で、順に消える）。
3. **消すのは、このアプリが送った記録だけ。** 印（タグ）が `data-agent` のものと、名前を変える前の `coding-agent` のものを消す。同じプロジェクトにほかのアプリの記録があっても、消さない。鍵はプロジェクトごとなので、ほかのプロジェクト（brew_app、studyops）の記録には届かない。
4. **消す前に、消す記録をすべて集めてから消す。** 消しながら一覧の頁をめくると、頁がずれて取りこぼすため。1 回の呼び出しで消すのは 1,000 件まで（Langfuse の上限）、1 回の実行で消すのは 20,000 件まで（残りは次の日）。
5. **Langfuse の API は、SDK の型を通さずに呼ぶ。読むのは、記録の ID と頁の数だけ。** SDK は、返ってきた記録の項目が 1 つ足りないだけで、全体を失敗にする（偽のサーバーで確かめたとき、そうなった）。Langfuse の版が上がって項目が変わっても、消す仕組みが止まらないようにする。Langfuse の説明書の、削除の例と同じ呼び方。
6. **送り先（`LANGFUSE_BASE_URL`）が書かれていなければ、消さない。** SDK の既定の送り先（Langfuse の公式のクラウド）に向けないため。
7. **消した数は、監査ログに残す**（`"event": "trace_retention"`。日数と件数だけ）。失敗したときは、エラーの種類だけを残す（エラーの文には、接続先などが入るため）。
8. **手でも確かめられるようにする。** `uv run python -m data_agent.storage.trace_retention` で、消す対象の件数だけを出す（消さない）。`--delete` を付けると、すぐに消す。`--days` で日数を変えて数えられる。

## 検討した案

| 案 | 内容 | 料金 | 判断 |
|---|---|---|---|
| **A. アプリが毎日、API で消す** | アプリの中で 1 日 1 回、古い記録を消す | 0 円 | **採用**。いまの構成のまま動く。AWS（ADR-0009）に移っても、同じ仕組みで動く |
| B. Langfuse の Enterprise 版の設定を使う | プロジェクトの設定画面で日数を決める | ライセンスの料金 | 不採用。料金がかかる |
| C. Langfuse のデータベース（ClickHouse）に、消す期限（TTL）を付ける | データベースが自動で消す | 0 円 | 不採用。Langfuse のデータベースを直接書き換えることになる。brew_app と studyops の記録も消える。Langfuse の版を上げたときに、設定が消えたり、壊れたりするおそれがある |
| D. Mac の launchd で、手元から消す | ADR-0024 の点検と同じ形 | 0 円 | 不採用。アプリが動いていれば足りるので、Mac への登録を増やさない。AWS に移ると使えない |

## 確かめたこと（2026-11-16）

- **単体テスト**（`tests/test_trace_retention.py` に 10 件。全体で 485 件すべて通った）:
  - 消すのは、日数より古い、このアプリの印の記録だけ（ほかのアプリの印、新しい記録は消さない）。2 つの印を持つ記録は 1 回だけ消す。
  - すべての頁を集めてから、1,000 件ずつ消す（2,350 件で 1,000・1,000・350）。1 回の上限で止まる。
  - 件数だけを出すときは消さない。0 日のときは、Langfuse に問い合わせもしない。設定の既定は 90 日、負の値は受け付けない。
  - 送り先が書かれていなければ、使わない。
  - つながらなかったら 1 時間後にやり直し、うまくいったら 24 時間待つ。監査ログには、エラーの種類だけを残す。
  - **手元に立てた偽の Langfuse に、実際に送った形:** `GET /api/public/traces`（`tags`、`toTimestamp` は UTC の Z 付き、`orderBy=timestamp.asc`、`fields=core`、頁ごと）と、`DELETE /api/public/traces`（`{"traceIds": [...]}`）。鍵が違って断られたときは、何も消さない。
- **手で動かすコマンド**（偽の Langfuse）: 件数だけ、`--delete`、`--days 0`、鍵の誤り（「断られました（401）」）、つながらない（「つながりませんでした」）の 5 通り。
- **アプリの起動**（Docker の中。イメージは `data-agent:local`、いまの `src` を重ねた。偽の Langfuse）: 鍵があれば見張りが動き、古い 2 件だけを消した（新しい 1 件は残した）。アプリを止めると見張りも止まる。日数を 0 にすると、見張りを動かさない。
- **画面の回帰確認:** 下の「結果」。

### 結果

- **画面の回帰確認:** 17 種類、368 項目がすべて通った（`logs/e2e/20261116-220115`）。使い捨てのコンテナは残っていない。回帰確認には Langfuse の鍵を入れていないので、消す見張りは動かない（起動の確認は、上の「アプリの起動」で行った）。
- **確認の途中で見つけた誤り（3 つ。どれも直して通した）:**
  - 1 回に消す数の上限を、関数を作った時点の値で固定していた（あとから変えても効かなかった）。
  - はじめは SDK の型を通して一覧を読んでいた。偽のサーバーが返す項目が足りないだけで、全体が失敗した。決定の 5 のとおり、ID だけを読む形に書き直した。
  - 起動の確認の台本が、止める指示を出した直後に「止まったか」を見ていた（台本の誤りで、アプリの誤りではない）。

## 分かっている制約

- **本物の Langfuse では、まだ動かしていません。** 鍵は `.env` にあり、こちらからは読まないためです。作り直したあとに、オーナーが件数だけを出すコマンドで確かめます（下の「次にやること」）。いまの記録は 11/13 からのものなので、90 日を過ぎた記録はまだなく、件数は 0 件のはずです。
- **消えるのは、アプリが動いている日だけです。** 止めている間の分は、次に起動してから 1 分後に消えます。
- **消すのは、Langfuse の記録（トレース）だけです。** 監査ログ（アプリのログ）、会話の保存（PostgreSQL）、依頼の記録（スキルの提案の材料。ADR-0007）は、別に決めます。
- **Langfuse の裏で消えるまでには、少し時間がかかります。** 消す指示を受け取ったあと、Langfuse が順に消します。
- **Langfuse の公開 API の形が変わったら、直す必要があります。** 一覧の形（`data` の `id` と、`meta.totalPages`）と、削除の形を使っています。
- **ほかのアプリが、同じ印（`data-agent` か `coding-agent`）を付けて、同じプロジェクトに送っていれば、その記録も消えます。**
