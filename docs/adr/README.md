## オーナーの判断待ち

1. **利用者とログイン方法**（ADR-0009）: AWS で動かすときの利用者の人数と、ログインの方法。
2. **コード実行の、AWS での構成**（ADR-0016）: AWS では、実行用のコンテナを別のサービスとして動かす。利用者ごとに分けるかも未決。実行のたびの承認は、既定では求めないことに決まった（2026-11-14）。
3. **スキルを利用者ごとに分けるか**（ADR-0007）: 登録したスキルは、いまは全員に効く。複数人で使う前に決める。依頼の記録を残す期間も未決。
4. **定時実行の言葉での登録**（ADR-0006）: いまは cron 式で書く。「毎朝9時に」のような言葉での登録に対応するか。
5. **左側の一覧の作り替え**（ADR-0011）: アーカイブとグループ分けは、チャットの中のコマンドで作った。使ってみて、一覧そのものを作り替えるかどうか。
6. **pgvector**（ADR-0010）: 手元の Langfuse の PostgreSQL を pgvector 入りのイメージに替えるか。Langfuse と、それを使う brew_app・studyops に影響する。
7. **保存した会話を残す期間**（ADR-0010、ADR-0011）: いつまで残すか。ツールの入力と出力も保存される。
8. **画面の方針**（ADR-0013）: Chainlit の標準の画面を使い続け、足りない操作はコマンド・ボタン・設定欄で補う、という方針でよいか。足す機能の順番。
9. **データベースの読み取り**（ADR-0017）: 種類は PostgreSQL、場所は手元の PostgreSQL（Langfuse と同じコンテナ）に決まった（2026-11-14）。そこには、今は練習用のデータベースしかないので、読ませるデータベースを用意する（オーナー）。ツールの形（結果を CSV に保存する、承認を既定では求めない）でよいか。本物のモデルでの動作は、オーナーが練習用のデータで確かめた（2026-11-14）。
10. **Web 検索**（ADR-0018）: Claude API の Web 検索ツールを使うことに決まった（2026-11-14）。チャットとは別の呼び出しに分ける形、検索に使うモデル（既定は Sonnet 5.5）、回数の上限でよいか。調べる先のドメインを絞るか。本物の API での動作は、オーナーが確かめた（2026-11-14）。実際にかかった料金は、まだ確かめていない。
11. **個人情報の守り方**（ADR-0019、ADR-0023）: 顧客の名前は、エージェントも読めるようにした（オーナーの決定。2026-11-15。ADR-0023）。列ごとに読めなくすることと、メールアドレス・電話番号をマスクすることに決まった（2026-11-14）。読ませるデータベースで、どの列を読めなくするかを決める（下書きは `--columns` が作る）。口座番号のルール、ビューの扱い、一覧のファイルを必須にしたことは、提案どおりの実装でよいか。メールアドレスと電話番号のマスクは、アプリの全体に効く（連絡先を扱う作業ができなくなる）が、それでよいか。オーナーの資料にあって取り入れていないもののうち、OWASP の基準は ADR-0020 で入れた。審判モデルと監視を、どこまで入れるか。
12. **OWASP の点検の続き**（ADR-0020）: 指示の乗っ取り（間接注入）の貫通率は、画面で選べる 3 つのモデルとも 0% で、基準（20% 以下）を満たした（2026-11-15）。モデル・プロンプト・ツールを変えたときに、測り直すか（`uv run python -m data_agent.evals.redteam --model all`。約 1 ドル。オーナーが実行する）。Web 検索は、質問文を調べて、怪しいときだけ確認する形にした（オーナーの決定。2026-11-15。ADR-0022）。新しい設定でも測り直し、3 つのモデルとも 0/21 だった（2026-11-15）。誤情報（LLM09）は、基準の案をひとまず使うことにし、3 つのモデルとも満たした（2026-11-15。ADR-0025）。使うときの守りとして、プロンプトの「数と出典」の決まりと、返事の照合・注記を入れた（ADR-0026）。プロンプトを変えたあとも、本物のモデルで測り直し、どちらも 3 つのモデルとも基準を満たした（オーナー。2026-11-15）。依存ライブラリの確認を、定期的に行う方法（提案: Mac の launchd で週に 1 回。ADR-0024）。→ 毎日に決まり、Mac に登録済み（2026-11-17）。
13. **確認（承認）のしかた**（ADR-0021）: 既定は「標準」（削除と長期メモだけ確認）でよいか。法人で使うときに、既定を「毎回確認」にするか、利用者が切り替えられないようにするか。「このチャットでは以後確認しない」を出してよいか（怪しい Web 検索には出さない）。時間切れを拒否として扱ってよいか。
14. **Web 検索の前の確認**（ADR-0022）: 何を怪しいとみなすか（番号やコード、表の値、長い文、見張る言葉）の細かい決まりでよいか。見張る言葉の一覧（顧客の名前など）を作るか。顧客の名前は、データベースから読んで見張る（オーナーの決定。名前を含む検索は確かめ、メールアドレスと電話番号を含む検索は断る。2026-11-15。ADR-0023）。
15. **次の用途と、つなぐ社内の API**（ADR-0032、ADR-0033）: 次に作る用途のパック。つなぐ社内の API（MCP でラップ済み。2026-11-17 にオーナーが伝えた）。鍵の権限（読むだけにできるか）。ツールごとの確認（書き換える・送るものは「毎回」）。MCP の結果に指示を仕込む攻撃を点検に足して、本物のモデルで測るか。画面の名前（ブラウザのタブ）を、パックごとに変えるか。

## ADR の追加と変更

- **いつ書くか:** 機能を足す・変える・やめるとき、守りの決まり・依存ライブラリ・外のサービス・データの持ち方を変えるとき、オーナーに選択肢を選んでもらったとき。動きを変えない直し（誤字、リファクタリング、整形）は書かなくてよい（AGENTS.md の「決めたことを残す（既定）」）。
- **ひな形:** [template.md](template.md) を写して書く。オーナーの言葉は「」で引用し、採らなかった案とその理由、確かめたこと、分かっている制約、次にやること、を書く。
- ファイル名は `NNNN-短い英語の名前.md`。番号は連番で、欠番を作らない。
- 既存の ADR の決定は書き換えない。決定を変えるときは新しい ADR を追加し、古いほうの状態を「置き換え済み（→ ADR-NNNN）」にする。
- 追加・変更したら、この一覧と、プロジェクト直下の [AGENTS.md](../../AGENTS.md) の表を更新する。
- 書いたら、`uv run --offline pytest -q tests/test_adr_records.py` で、書き方（状態・日付・決定者、状況、決定）と、一覧の漏れを確かめる。
