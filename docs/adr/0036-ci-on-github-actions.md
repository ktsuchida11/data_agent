# ADR-0036: GitHub に送るたびに、整形・点検・単体テストを GitHub Actions で流す（CI）

- **状態:** 採用（実装済み）。オーナーが決めた（2026-11-18。「CIも入れてください」）
- **日付:** 2026-11-18
- **決定者:** プロジェクトオーナー
- **対象:** data_agent

## 状況

- ADR-0035 で、変更の記録を git で残し、GitHub の非公開のリポジトリ `ktsuchida11/data_agent` に置いた。
- ADR-0034 で、コードを変えたら `ruff format`・`ruff check`・`pytest` を通す決まりにした。ただし、通したかどうかは、作業した人（AI を含む）に任せていた。
- 料金: GitHub Actions は、非公開のリポジトリなら、無料のプランで月 2,000 分まで無料。

## 決定

1. **GitHub に送るたびに、GitHub Actions で 3 つを流す。** `ruff format --check`（整形の確かめ）、`ruff check`（書き方とセキュリティの点検）、`pytest -q`（単体テスト）。設定は `.github/workflows/ci.yml`。
   - 流れるとき: `main` に送ったとき、プルリクエストを作ったとき、GitHub の画面から手で流したとき。
   - 依存は `uv sync --frozen`（`uv.lock` のとおり）。uv の版は手元と同じ（0.11.6）。Python は `.python-version`（3.12）。
2. **本物のモデルは呼ばない。** API キーなどの秘密の値は、CI に渡さない。単体テストは偽のモデルで動く。
3. **権限は「読むだけ」にする。** `permissions: contents: read`。取り出したあと、GitHub の鍵を残さない（`persist-credentials: false`）。
4. **使う部品（アクション）は、中身が変わらない ID（コミットの番号）で固定する。** 版の名前（`v7` など）は、あとから中身をすり替えられるため。版はコメントに書く。`actions/checkout` v7.0.1、`astral-sh/setup-uv` v10.3.3（どちらも、出てから 2 週間以上たった版）。
5. **無料の分数を守る。** 同じ枝に続けて送ったら、古いほうを止める（`concurrency`）。1 回の上限は 15 分。
6. **画面の回帰確認（`tests/e2e/regress.sh`）と、依存の脆弱性の点検は、CI に入れない。** 回帰確認は手元で流す。脆弱性の点検は、Mac の毎日の点検（ADR-0024）に任せる。

## 検討した案

| 案 | 内容 | 判断 |
|---|---|---|
| **A. 整形・点検・単体テストを、GitHub Actions で流す** | 送るたびに数分 | **採用**。無料の分数に十分に収まる。手元で流し忘れても気づける |
| B. A に、画面の回帰確認も足す | Docker のイメージを作り、使い捨ての PostgreSQL を立てる | 今は不採用。1 回 10 分以上かかり、月 2,000 分では、多くても 200 回ほどしか流せない。手元のイメージ（`data-agent:local`）を前提にした作りでもある |
| C. A に、依存の脆弱性の点検（`uv audit`）も足す | 送るたびに調べる | 今は不採用。Mac で毎日調べている（ADR-0024）。新しい脆弱性が出ただけで、変更と関係なく CI が落ちる |
| D. 記録（コミット）の前に、手元で自動で流す（pre-commit） | 通らないと記録できない | 今は不採用。道具が 1 つ増える。CI で同じことを確かめられる |
| E. 自前の CI（Jenkins など） | 手元か AWS に立てる | 不採用。無料だが、サーバーの運用を自分でする必要がある |

## 確かめたこと（2026-11-18）

- **手元:** 単体テスト、`ruff format --check`、`ruff check` が通った。設定ファイルは YAML として読めた。
- **GitHub:** 送ったあと、CI が最後まで通ったことを、`gh run watch` で確かめた。

## 分かっている制約

- **CI が落ちても、`main` への送信は止まらない。** 無料のプランでは、非公開のリポジトリに「CI が通らないと取り込めない」設定（ブランチの保護）を使えない（GitHub に尋ねると「Upgrade to GitHub Pro or make this repository public」と返った。2026-11-18）。落ちたことは、GitHub の通知や、リポジトリの Actions の画面で分かるので、そこで直す。
- **本物のモデル、Docker の中での確認、画面の回帰確認は、CI では確かめない。** 料金がかかるもの（本物のモデルでの点検）は、これまでどおりオーナーが流す。
- **使う部品の版は、自動では上がらない。** 上げるときは、新しい版のコミットの番号を調べて書き換える。
