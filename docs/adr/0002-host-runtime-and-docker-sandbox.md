# ADR-0002: アプリ本体はホストで直接動かし、Docker はコード実行の隔離だけに使う

- **状態:** 一部置き換え済み（→ ADR-0009、ADR-0016）。アプリ本体はコンテナでも動かせるようになり、最終的には ECS で動かす。コード実行の隔離は ADR-0016 で作った
- **日付:** 2026-11-13（設計はフェーズ1の時点のもの）
- **決定者:** プロジェクトオーナー

## 状況

「data_agent はコンテナで動くのか」という質問が出たので（2026-11-05）、現行の動かし方を記録します。

## 決定（現行の設計）

- **アプリ本体はコンテナに入れません。** Chainlit の画面とエージェントは、Mac 上で `uv` を使って直接動かします。Dockerfile や compose ファイルはありません。
- **エージェントが触れる範囲は、仮想ファイルシステムと権限ルールで絞ります。** 見えるのは `workspace/`、`memories/`、`skills/` だけで、`config/`、`.env`、`src/` は見えません。
- **Docker は、エージェントが書いたコードを実行する場所としてだけ使う計画です。** フェーズ2で作る予定で、まだ着手していません。
- **customer_needs_agent は別のプロジェクトです。** data_agent とは連携せず、ターミナルから単独で動かします。

## 影響

- 今はコードやテストを実行できません。できるのはファイルの読み書きだけです。
- アプリは起動している間しか動きません。常駐するサービスではないので、Mac のスリープ中や停止中は何も実行されません。定時実行をローカル版で作る場合の制約になります（ADR-0006）。
- 画面は `127.0.0.1` で待ち受け、ユーザー名とパスワードでログインします。

## 追記（2026-11-13）

アプリ本体をコンテナで動かすための `Dockerfile` と `compose.yaml` を追加しました。
手元では、`uv` で直接動かす方法と、コンテナで動かす方法の両方が使えます。

## 未決事項

- 最終的な実行環境は AWS の ECS に決まりました（ADR-0009）。Fargate ではコンテナの中から Docker を起動できないので、フェーズ2の設計は作り直します。コード実行が必要かどうかも含めて、ADR-0009 の「次にやること」で決めます。

## 追記（2026-11-14）

コード実行は必要と決まり、専用のコンテナを常駐させる形で作りました（ADR-0016）。アプリがコンテナを起動する形ではないので、Fargate でも使えます。
