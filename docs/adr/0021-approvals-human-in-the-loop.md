# ADR-0021: 操作の前の確認（承認）は、チャットごとに「標準／毎回確認」を選べるようにする

- **状態:** 採用（実装済み）。「権限や確認のための、人による確認（Human in the Loop）を入れる」ことは、オーナーが決めた（2026-11-14）。次の点は、提案どおりに実装した。オーナーの確認はまだ取れていない: 確認のしかたを2段階にしたこと、既定を「標準」にしたこと、「このチャットでは以後確認しない」を付けたこと、時間切れの扱い。Web 検索を、標準でも、怪しいときは確認することは、オーナーが決めた（2026-11-15。ADR-0022）
- **日付:** 2026-11-14
- **決定者:** プロジェクトオーナー
- **対象:** data_agent

## 状況

- オーナーから、「権限とか確認のための Human In The Loop の処理も入れてください」という依頼がありました（2026-11-14）。OWASP の点検（ADR-0020）と同じ日です。
- それまでも、確認の仕組みはありました。ファイルの削除と、長期メモ（`/memories/`）への書き込みは、必ず確認する。コードの実行・データベースの問い合わせ・Web 検索は、設定ファイルで `require_approval: true` にすると確認する（既定は確認しない。コードの実行は、オーナーが 2026-11-14 に決めた）。
- 足りなかったのは、次の点です。
  - 確認するかどうかは、設定ファイルでしか変えられず、利用者がチャットごとに選べなかった。
  - ファイルの作成と書き換えは、確認する方法がなかった。
  - 確認の画面は、ツールの名前と引数（JSON）を出すだけで、何が起きるのかが分かりにくかった。長い引数は、黙って途中で切っていた。
  - 答えは「承認」か「拒否」だけで、拒否の理由を伝えられなかった。同じ操作を何度も聞かれるのを、止める方法もなかった。

## 決定

- **確認のしかたを2段階にして、チャットごとに選べるようにします。** 画面の設定欄（モデルを選ぶのと同じ場所）で選びます。

| 操作 | 標準 | 毎回確認 |
|---|---|---|
| ファイルの削除 | 確認する | 確認する |
| 長期メモ（`/memories/`）への書き込み | 確認する | 確認する |
| ファイルの作成、書き換え | 確認しない | 確認する |
| コードの実行 | 確認しない（設定で変えられる） | 確認する |
| データベースの問い合わせ | 確認しない（設定で変えられる） | 確認する |
| Web 検索 | 外に出したくない情報らしいものがあるときだけ確認する（2026-11-15 から。ADR-0022） | 確認する |
| 読むだけの操作（ファイルを読む、表の一覧） | 確認しない | 確認しない |

- **新しいチャットの既定は「標準」です。** これまでと同じ動きです。`config/security.yaml` の `approvals.default_mode` で変えられます。
- **確認の画面には、何が起きるかと、なぜ聞いているかを、言葉で出します。** 書き込む内容、コード、SQL、検索の質問文も出します。
- **答えは4つです。**「承認」「承認（このチャットでは以後確認しない）」「拒否」「拒否して理由を伝える」。
- **「以後確認しない」は、削除と長期メモへの書き込みには出しません。**
- **サブエージェントにも、同じ決まりが効きます。** 調べるだけのサブエージェント（explorer）は、そもそも書き込めません（ADR-0020）。
- **定時実行（無人）では、確認が必要な操作は、自動で拒否します**（ADR-0006 のまま）。

## 仕組み

| 部品 | 役割 |
|---|---|
| `src/data_agent/safety/approvals.py` | どの操作を確かめるかの決まり（`ApprovalPolicy`）と、画面に出す説明。エージェントと画面の両方が、同じものを使う |
| `src/data_agent/agent.py` の `approval_policy()` | 設定ファイルと権限の決まりから、上の決まりを作る。`create_deep_agent` の `interrupt_on` に渡す |
| `src/data_agent/ui/app.py` | 確認の画面（ボタン）、設定欄、「以後確認しない」、止まっていた操作の再開 |
| `config/security.yaml` の `approvals` | 既定の確認のしかた、利用者が切り替えられるか、「以後確認しない」を出すか、答えを待つ時間 |

確かめる理由は5種類あり、画面に出します。

| 種類 | 対象 | 「以後確認しない」 |
|---|---|---|
| 守られた場所 | 権限の決まり（`agent.PERMISSIONS`）で「承認が必要」とした場所への書き込み。いまは `/memories/` | 出さない |
| 取り消せない操作 | ファイルの削除 | 出さない |
| 設定 | `config/security.yaml` で `require_approval: true` としたツール | 出す |
| 怪しい中身 | `require_approval: auto` としたツール（いまは Web 検索）で、質問文に、外に出したくない情報らしいものが見つかったもの（ADR-0022） | 出さない |
| 毎回確認 | 「毎回確認」のチャットでの、書き込み・実行・問い合わせ・検索 | 出す |

## 設計で気を付けたこと

**確認のしかたは、会話の状態に入れる。**
LangChain の確認の仕組み（`HumanInTheLoopMiddleware`）は、止まるかどうかの判定を、再開のときにもう一度行います。判定が途中で変わると、**利用者が拒否した操作が、そのまま実行されます**（ライブラリの注意書きにある動き）。設定の値をその場で読む作りにすると、確認を待っている間に設定欄を変えただけで、これが起きます。そこで、選んだ確認のしかたを、会話の状態（`approval_mode`）に入れてエージェントに渡します。状態は会話と一緒に保存されるので、止まったときと再開のときで、必ず同じ判定になります。アプリを再起動しても、チャットを開き直しても同じです。

**「以後確認しない」は、エージェントの外で扱う。**
同じ理由で、「以後確認しない」を選んでも、エージェントの判定は変えません。エージェントは毎回止まり、画面の側が、利用者に聞かずに承認を返します。監査ログには、自動で承認したことが残ります。チャットを開き直すか、確認のしかたを選び直すと、取り消されます。

**答えは「承認」と「拒否」だけを受け付ける。**
ライブラリの既定では、「引数を書き換えて実行する」「ツールの代わりに答える」という答えも受け付けます。画面はこれらを送らないので、受け付けないようにしました。

**確認の画面に、偽の説明を書き込めないようにする。**
画面に出す内容（書き込む文章、ファイルの場所）は、モデルが作ったものです。枠の記号や改行を入れて、「承認済みです」のような文章を画面に書き足すことができないようにしました。長い内容は、先頭と末尾を出し、省いた文字数と全体の長さを必ず書きます。値は、ガードレールでマスクしてから出します。

**別の画面で先に答えが出ていたら、あとの答えは使わない。**
確認を待ったまま画面を閉じて、開き直すと、もう一度確認が出ます。そちらで答えたあとに、閉じた側の待ち時間が切れても、その「時間切れ（拒否）」は使いません。

## 検討した選択肢

| | A. 2段階をチャットごとに選ぶ（採用） | B. 設定ファイルだけで決める（これまで） | C. すべての操作を、いつも確認する |
|---|---|---|---|
| **追加の料金** | なし | なし | なし |
| **利用者が選べるか** | 選べる（管理者が固定もできる） | 選べない | 選べない |
| **手間** | 標準では、これまでと同じ | これまでと同じ | 操作のたびにボタンを押す。定時実行で、何もできなくなる |
| **見落とし** | 標準では、書き込み・実行・検索は確認なしで進む | 同じ | 少ない。ただし、確認が多すぎると、中身を見ずに押すようになる |

C にしなかった理由は、コードの実行を確認なしにする、というオーナーの決定（2026-11-14）と、定時実行が使えなくなることです。

## 確かめたこと（2026-11-14）

**単体テスト（`tests/test_approvals.py`）**
- 操作と確認のしかたの組み合わせ 27 通りで、確かめるかどうかが決まりどおりになる。
- 確認のしかたが会話の状態に入り、止まったあとで再開しても同じ判定になる。拒否した操作は実行されない。
- 「引数を書き換えて実行する」答えは、受け付けない。
- 内容に枠の記号があっても、枠が途中で閉じない（4 例）。ファイルの場所に改行や記号を入れても、説明の行に書き足せない（4 例）。

**アプリとつないだ状態（偽のモデル。`tests/e2e/check_approvals.py` の 70 項目と、`locked` の 14 項目）**
- 標準では、削除と長期メモと、怪しい Web 検索を聞かれる（Web 検索は、2026-11-15 から。ADR-0022）。毎回確認では、書き込み・書き換え・コードの実行・問い合わせ・検索も聞かれ、読むだけの操作は聞かれない。
- 拒否すると実行されない。承認すると実行される。何を承認・拒否したかが、画面に残る。
- 拒否の理由が、モデルに伝わる。理由の中のキーは、マスクされてから渡り、履歴にも残らない。
- サブエージェントの書き込みも聞かれる。調べるだけのサブエージェントは、聞かれる前に断られる。
- 1回の返事に複数の操作が入っているときは、1つずつ聞かれ、承認したものだけが実行される。
- 「以後確認しない」を選ぶと、同じ操作は聞かれなくなる。別の操作、削除、長期メモは、引き続き聞かれる。確認のしかたを選び直すと、取り消される。
- チャットを開き直すと、前に選んだ確認のしかたが出る。確認を待ったまま閉じても、開き直すともう一度聞かれる。
- 利用者が切り替えられない設定では、設定欄に出ず、通信で切り替えようとしても断られる。
- 時間内に答えないと、実行されない。
- 定時実行では、確認が必要な操作は自動で拒否され、登録のときに、その操作の一覧が示される。

**実際のブラウザ**
- 確認の画面に、説明・理由・内容・ボタンが出る。「拒否して理由を伝える」を押すと、理由を書く欄が出て、書いた理由がモデルに伝わる。

**本物のモデル（オーナーが確認。2026-11-14）**
- アプリを作り直して動かし、確認の画面に承認のボタンが出た（オーナーの報告）。

**確認していないこと**
- **本物のモデルでの、拒否のあとの動き。** 拒否されたあとに、モデルが別の方法を探すか、理由に沿ってやり直すかは、使ってみないと分かりません。
- 「毎回確認」で実際の作業をしたときに、確認が多すぎないか。

## 分かっている制約

- **標準では、ファイルの作成と書き換え、コードの実行、データベースの問い合わせは、確認なしで進みます。** 既にあるファイルも、確認なしで上書きされます。Web 検索は、2026-11-15 から、質問文に外に出したくない情報らしいものがあるときだけ確認します（`web_search.require_approval: auto`。ADR-0022）。
- **「以後確認しない」は、ツールの単位です。** 「ファイルを書く」を選ぶと、そのチャットでは、どのファイルへの書き込みも聞かれなくなります（長期メモは除く）。怪しい Web 検索の確認には出しません。
- **確認の内容は、エージェントが実行しようとしている操作そのものです。** その操作が妥当かどうかの判断は、人がします。長い内容は、途中を省いて出します（省いたことは書きます）。
- **時間切れは、拒否として扱います。** 席を外している間に聞かれた操作は、実行されないまま、エージェントが先へ進みます。
- **誰でも承認できます。** 利用者は、いまは1人です。「承認できる人を分ける」仕組みはありません。
- **「引数を書き換えて承認する」ことはできません。** 拒否して、理由を伝えてください。

## 見直す条件

- 複数人で使うようになったとき（承認できる人を分けるか、承認の記録をどこに残すかを決める）。
- 「毎回確認」が煩わしいと分かったとき（ファイルの場所や、操作の中身で細かく分けるかを決める）。
- 定時実行で、確認が必要な操作を使いたくなったとき（登録のときに、先に許可しておく形にするかを決める）。
