# ADR-0014: モデルは、画面の設定欄からチャットごとに切り替えられるようにする

- **状態:** 採用
- **日付:** 2026-11-13
- **決定者:** プロジェクトオーナー
- **対象:** data_agent

## 状況

- これまで、モデルは `.env` で指定し、変えるにはアプリの再起動が必要でした（ADR-0005）。
- 画面から切り替えたい、という要望がありました。置き場所は設定欄にする方針です（ADR-0013）。

## 決定

- **入力欄の設定ボタンから、チャットごとにモデルを選べるようにします。**
- **選べるモデルは `.env` の `MODEL_CHOICES` で決めます。** 既定は Opus 5.5、Sonnet 5.5、Haiku 5.5 の3つです。
- **新しいチャットは、`MAIN_MODEL` のモデルで始まります。**
- **選んだモデルは、チャットごとに覚えます。** 過去のチャットを開き直すと、前に選んだモデルで続きます（過去のチャットを保存しているときだけ）。
- **画面から送られてきたモデル名は、選べるモデルに入っているかを必ず確かめます。**

## 仕組み

- モデルごとにエージェントを1つずつ作り、使い回します。会話は保存先にあるので、途中でモデルを替えても、同じ会話の続きとして話せます。
- 選んだモデルは、`Thread` の表の `modelName` 列に保存します。最初のメッセージを送る前はチャットがまだ保存されていないので、メッセージを処理したあとに保存します。

| 対象 | 使うモデル |
|---|---|
| メインのエージェント | 画面で選んだモデル |
| 汎用のサブエージェント | 画面で選んだモデル |
| 調査用のサブエージェント（`explorer`） | `FAST_MODEL`（画面の選択では変わらない） |

- 推論の深さ（`MAIN_EFFORT`）は、どのモデルを選んでも同じ値を使います。
- 安全分類器に断られたときのフォールバック（`ENABLE_REFUSAL_FALLBACK`）は、対応するモデルを選んだときだけ有効になります。Haiku 5.5 には、サーバー側のフォールバックがありません。

## 検討した選択肢

| | A. モデルごとにエージェントを作る（採用） | B. 1つのエージェントで、呼び出しのたびにモデルを差し替える |
|---|---|---|
| **仕組み** | 選べるモデルの数だけ、エージェントを用意する | ミドルウェアで、モデル呼び出しの直前にモデルを差し替える |
| **作る量** | 小 | 中（選んだモデルを、サブエージェントの呼び出しまで運ぶ必要がある） |
| **メモリの使用** | モデルの数だけ増える（使ったモデルの分だけ作る） | 増えない |

A を選びました。選べるモデルは数個で、作りが単純なためです。

## 影響

- **途中でモデルを替えると、その直後の1回は入力の料金が割引なしになります。** プロンプトのキャッシュはモデルごとに分かれているためです。
- **それまでの思考の記録は、そのまま次のモデルに送ります。** Claude API の資料によると、次のモデルが読めないものは API の側で無視され、料金もかかりません。
- **高いモデルを選べるようにすると、料金が上がります。** たとえば Fable 5.2 は、Opus 5.5 の2倍の料金です。既定の選択肢には入れていません。

## 確かめたこと（2026-11-13）

使い捨ての PostgreSQL と偽のモデルを使い、画面と同じ通信で確かめました。偽のモデルは、どのモデルとして呼ばれたかを返事に付けて返します。

**確認できたこと**
- 設定欄に、選べるモデルと、いま選ばれているモデルが届く。
- モデルを替えると、次の返事から替えたモデルが使われる。会話は続きになる（返事が「2通目」になる）。
- 選べるモデルにない名前を送ると、断られる。前に選んだモデルのまま続く。
- チャットを開き直すと、設定欄に前に選んだモデルが出て、そのモデルで続く。
- 新しいチャットは、既定のモデルで始まる。

**確認していないこと**
- 本物のモデルでの切り替え。途中でモデルを替えたときに、API がエラーを返さないこと。
- ブラウザの画面での、設定欄の見た目と操作。
