# ADR-0016: コードの実行は、専用のコンテナ（Docker）で行い、ファイルを受け渡す形にする

- **状態:** 採用（実装済み）。実行する場所を自前の Docker にすることと、実行のたびの承認を既定では求めないことは、オーナーが決めた（承認については 2026-11-14 に確認）。別のコンテナにすることと、ファイルを受け渡すことは、提案どおりに実装した。本物のモデルでの動作は、オーナーが確認した。AWS での構成は未定。→ 2026-11-18: 実行のあとに残ったプロセスは、なくなるまで繰り返し止めるようにした。止めきれなければサーバーを止め、コンテナを起動し直させる（ADR-0034）
- **日付:** 2026-11-14
- **決定者:** プロジェクトオーナー
- **対象:** data_agent

## 状況

- コード実行の主な用途は、データの可視化、表の作成、Excel・PowerPoint の出力、PDF の読み込みです（オーナー、2026-11-14）。テストやコマンドを動かすことが主な目的ではありません。
- 実行する場所の候補は3つありました。オーナーは、追加の料金がかからない自前の Docker を選びました。
- 作り方には、次の2つの制約があります。
  - **ECS の Fargate では、コンテナの中から別のコンテナを起動できません**（ADR-0009）。
  - **Deep Agents 標準の `execute` ツールは、ファイルの権限の決まりと同時に使えません。** 有効にすると、`.env` や鍵ファイルの読み書きを禁止する決まり（`agent.py` の `PERMISSIONS`）を付けた時点でエラーになります（deepagents 0.7.32 で確認）。

## 決定

- **コードは、アプリとは別の常駐コンテナ（`sandbox/`）で実行します。** アプリがコンテナを起動する形にはしません。
- **実行できるのは Python のコードだけです。** エージェントのツールは `run_python` で、Deep Agents 標準の `execute` は使いません。
- **実行する環境には、作業フォルダを見せません。** ファイルは、アプリが権限を確かめてから受け渡します。
- **実行する環境は、インターネットにも、データベースにもつなぎません。**
- **実行のたびの承認は、既定では求めません。** 設定（`code_execution.require_approval`）で、承認制に変えられます。

## 仕組み

| 段階 | 内容 |
|---|---|
| **呼び出し** | モデルが `run_python` に、コードと、使いたいファイルのパス（`input_files`）を渡す |
| **入力の確認** | アプリが、ファイルごとに権限の決まりを確かめる。読めない決まりのファイル（`.env`、鍵、`.git/`）は渡さない |
| **実行** | 実行用のコンテナが、実行ごとの一時フォルダにファイルを置き、コードを動かす。既定は 60 秒、最大 300 秒 |
| **出力の受け取り** | コードがカレントフォルダに作ったファイルを、アプリが受け取る。秘密情報らしい文字列を含む文章のファイルと、書けない決まりの名前のファイルは保存しない |
| **保存** | 作業フォルダの `outputs/<日時>-<乱数>/` に保存する |
| **表示** | 画像はチャットにそのまま表示し、ほかのファイルはダウンロードできる形で出す |
| **後片付け** | 実行用のコンテナが、一時フォルダと、残っているプロセスをすべて消す |

実行用のコンテナに入っているライブラリは、pandas、numpy、matplotlib、openpyxl、xlsxwriter、python-pptx、python-docx、pypdf、pdfplumber、pillow、tabulate です。グラフに日本語を描けるよう、日本語フォントを入れてあります。

| ファイル | 役割 |
|---|---|
| `sandbox/server.py` | 実行用のコンテナの中で動くサーバー。標準ライブラリだけで書いてある |
| `sandbox/Dockerfile`、`sandbox/requirements.txt` | 実行用のコンテナの定義と、入れるライブラリ（版とハッシュを固定） |
| `src/data_agent/tools/code_execution.py` | `run_python` ツール。ファイルの受け渡しと、権限の確認 |
| `compose.yaml` の `sandbox` | 実行用のコンテナの起動のしかた（ネットワーク、上限） |
| `config/security.yaml` の `code_execution` | 時間、ファイルの数と大きさ、承認の要否 |

## 守り

- **外へ出られない。** 実行用のコンテナは、アプリとだけつながる専用のネットワーク（`internal: true`）に置きます。インターネットにも、PostgreSQL にも届きません。
- **秘密情報を持たせない。** `.env` も、アプリのコードも、作業フォルダも、実行用のコンテナには渡しません。
- **書き込める場所は、メモリ上の一時フォルダだけ。** それ以外は読み取り専用です。一般ユーザーで動かし、特権はすべて外しています。
- **使える資源に上限がある。** メモリ 1GB、CPU 1つ、プロセス 256 個、時間は最大 300 秒です。
- **実行をまたいで何も残さない。** 実行は1件ずつ行い、終わるたびに、プロセスとファイルを片付けます。
- **出力はガードレールを通る。** 標準出力は、ほかのツールの結果と同じく、モデルに渡る前にマスクされます。
- **調べるだけのサブエージェント（`explorer`）には持たせない。**

## 検討した選択肢

| | A. Claude API のコード実行 | B. AWS の AgentCore Code Interpreter | C. 自前の Docker（採用） |
|---|---|---|---|
| **動く場所** | Anthropic の環境 | AWS アカウントの中 | 手元。AWS では自分の ECS |
| **追加の料金** | 月 1,550 時間まで無料 | 使った分 | なし |
| **データの置き場所** | Anthropic の側に置かれる | AWS の中 | 手元から出ない |
| **作る量** | 小 | 中 | 大 |
| **Claude 以外のモデル** | 使えない | 使える | 使える |

自前の Docker の中でも、2つの形を比べました。

| | アプリが実行のたびにコンテナを起動する | 専用のコンテナを常駐させる（採用） |
|---|---|---|
| **隔離** | 実行ごとに作り直すので、いちばん強い | 同じコンテナを使い回す。実行のたびに片付ける |
| **AWS（Fargate）** | 使えない | 別のサービスとして動かせる |
| **アプリに要る権限** | Docker を操作する権限（強い権限） | なし |

## 確かめたこと（2026-11-14）

偽のモデルと、使い捨ての PostgreSQL を使って確かめました。

**実行用のコンテナ単体（28 項目。`tests/e2e/check_sandbox.py`）**
- 日本語のグラフ、Excel、PowerPoint を作れる。PDF から文字を取り出せる。表（Markdown）にできる。
- インターネットに出られない。決まった場所のほかには書き込めない。
- 時間切れで止まる。メモリを使いすぎたコードは止められ、サーバーは動き続ける。
- 裏で起動したプロセスと、置いていったファイルは、次の実行に残らない。
- コードから、サーバーの環境変数（トークン）を読めない。
- `compose.yaml` に書いた定義そのもので起動しても、同じ結果になる。

**アプリとつないだ状態（28 項目と、承認制の 2 項目。`tests/e2e/check_code_execution.py`）**
- 作業フォルダのファイルを渡して集計できる。作ったファイルが `outputs/` に保存される。
- 画像がチャットに表示され、Excel と PowerPoint をダウンロードできる。
- `.env` や `.git/` の中のファイルは、コードに渡せない。
- コードから、インターネットにも、データベースにも届かない。
- 出力に出たキーは、モデルに渡る前にマスクされる。キーを含むファイルは保存されない。
- 汎用のサブエージェントは実行でき、調べるだけのサブエージェントは実行できない。
- 定時実行（無人）でも動く。
- 承認制にすると、拒否したときは実行されず、承認したときだけ実行される。

これまでの機能（スキルの提案、定時実行、モデルの切り替え、ガードレール、一覧・再開・削除、アーカイブ・グループ分け）も、引き続き通りました。単体テストは 135 件が通ります。

**確認の途中で見つけて直したこと**
- コードから、実行用のサーバーのトークンを読めた（コンテナの最初のプロセスの環境変数として見えていた）。サーバー自身を最初のプロセスにして、読めないようにした。
- アプリのコンテナで、画像やファイルを画面に出せなかった（Chainlit の一時フォルダに、アプリのユーザーが書き込めなかった）。`compose.yaml` で書き込めるようにした。

**オーナーが本物のモデルで確認したこと（2026-11-14）**

`docker compose up --build` で起動し、ブラウザから次の3つを依頼して、「全部できることを確認しました」との報告を受けました。

| 依頼 | 確かめた内容 |
|---|---|
| 1〜12月の売上のサンプルを作って、棒グラフにして | チャットに画像が出る |
| 同じデータを Excel と PowerPoint にして | ファイルを受け取って開ける |
| `workspace/` に置いた PDF の要点をまとめて | PDF を読める |

使ったモデルと、グラフや資料の細かい出来（日本語の表示など）についての報告は受けていません。

**確認していないこと**
- AWS（ECS）での動作。
- 承認制（`require_approval: true`）にしたときの、本物のモデルでの動き。偽のモデルでは確認済みです。
- 定時実行（無人）からの、本物のモデルでのコードの実行。偽のモデルでは確認済みです。

## 分かっている制約

- **コンテナで起動したときだけ使えます。** `uv run` で直接起動したときは、`run_python` は付きません。
- **実行は1件ずつです。** ほかの実行が終わるのを 30 秒まで待ち、それでも空かなければエラーを返します。
- **同じコンテナを使い回します。** 実行のたびに片付けますが、コンテナそのものは作り直しません。複数人で使う前に、利用者ごとに分けるか、実行のたびに作り直すかを決める必要があります。
- **実行用のコンテナから、アプリの画面のポートには届きます。** 同じネットワークにいるためです。ログインしないと中身は見られません。AWS では、通信を許す向きをセキュリティグループで絞ります。
- **Excel や PowerPoint の中身は、ガードレールで調べられません。** 調べられるのは、標準出力と、文章のファイルだけです。
- **開き直したチャットでは、画像は表示されません。** ファイルは作業フォルダに残っていて、保存先のパスはメッセージに書いてあります。
- **`outputs/` のファイルは、自動では消えません。**
- **ライブラリを足すには、イメージを作り直します。** `sandbox/requirements.in` に書き足して、`requirements.txt` を作り直します。
- **AWS では、実行用のコンテナを別のサービスとして動かす必要があります。** アプリと同じタスクに入れると、ネットワークを共有してしまい、外へ出られる状態になるためです。
