# ADR-0033: 社内の API を、MCP（HTTPS）でつなぐ。使うツールを名指しし、鍵は .env、社内の認証局は ca_file で

- **状態:** 採用（実装済み）。オーナーが決めた（2026-11-17。「MCP サーバを追加できるようにする」「社内の API で HTTPS でアクセスする」）。README の「フェーズ 4」の MCP に当たる。決定 9（MCP でない API を Python のツールから呼ぶ部品）は、同じ日に取りやめた（オーナー: 社内の API は MCP でラップ済み）
- **日付:** 2026-11-17
- **決定者:** プロジェクトオーナー
- **対象:** data_agent

## 状況

- 別の用途に広げるには、社内のシステムにつなぐ必要がある。最初につなぐのは、HTTPS で使う社内の API。
- MCP（Model Context Protocol）は、エージェントにツールを足すための共通の決まり。社内の API を MCP サーバーとして公開すれば、コードを書かずに設定だけでつなげる。
- 社内の API は、次のような形が多い。
  - 社内の認証局が発行した証明書を使う。ふつうの確かめ方では、つながらない。
  - 鍵（トークン）を、ヘッダーで送る。
- MCP サーバーは、アプリの外のもの。返す説明と結果に、指示が仕込まれていることがある。説明に仕込むものは、ツールの説明への仕込みと呼ばれる。
- オーナーは、料金のかからない、自前の構成を好む。

## 決定

1. **LangChain の `langchain-mcp-adapters`（無料）で、アプリの中から MCP サーバーを呼ぶ。** MCP のツールの呼び出しも、ほかのツールと同じ守りを通る（ガードレール、確認、回数の上限、監査ログ。ADR-0032）。
2. **つなぎ方は、HTTP（streamable HTTP）だけ。**
   - `https://` を使う。`http://` は、`allow_http: true` と書いたときだけ使える（同じ PC や、コンテナのネットワークの中だけで使う）。
   - アプリの中で別のプログラムを動かす形（stdio）は、いまは使わない。
3. **つなぐサーバーと、使うツールは、用途パックの `pack.yaml` の `mcp_servers` に書く。**
   - **使うツールの名指し:** 使うのは、`tools` に書いたツールだけ。サーバーにほかのツールがあっても、エージェントには見せない。
   - **名前:** ツールの名前は「サーバーの名前__ツールの名前」にする（組み込みのツールや、ほかのサーバーと重ならないように）。
   - **確認:** 確認の既定は「毎回」（`require_approval: true`）。読むだけのツールは、`false` にする。
4. **鍵は、`.env` に置く。** `pack.yaml` には `${環境変数名}` と書く。
   - **鍵のヘッダー:** 鍵を入れることが多いヘッダー（`Authorization`、`Cookie`、名前に token・key・secret などを含むもの）は、`${…}` で書かなければ、起動を止める。
   - **URL:** 名前やパスワードを書いた URL も、受け付けない。
   - **`.env` にないとき:** 環境変数の名前だけを知らせて、起動を止める（値は出さない）。
5. **社内の認証局の証明書は、`ca_file` に指定する。**
   - **信用する範囲:** 指定すると、その認証局が発行した証明書だけを信用する。指定しなければ、ふつうの確かめ方（公的な認証局）。
   - **リダイレクト:** 追わない。鍵を付けたまま、別の場所へ送らないため。
   - **プロキシ:** プロキシの環境変数と `.netrc` は使わない。
6. **サーバーが返す説明と結果は、外から来たデータとして扱う。**
   - **説明:** ガードレールで調べてから見せる。長さは 2,000 文字で切る。`pack.yaml` の `description` で、自分で書いた説明に差し替えられる。（→ 2026-11-18: 引数の説明・題名・例も、ガードレールで調べて 300 文字で切るようにした。引数の説明は差し替えられないため。ADR-0034）
   - **結果:** 会話に入る前にガードレールでマスクし（ほかのツールと同じ）、`max_output_chars`（既定は 20,000 文字）で切る。
   - **構造化した結果:** サーバーが返す「構造化した結果」（structuredContent）は使わない。マスクを通らずに、会話の保存先に残るため。
   - **引数:** 送る前に、秘密情報や個人情報がないかを確かめる（`check_arguments`。既定は「確かめる」。ADR-0032）。
7. **つなぐのは、アプリの起動のとき。** つながらない、または書いたツールがサーバーにないときは、理由を日本語で書いて、起動を止める。
   - **理由の例:** 鍵が違う、証明書を確かめられない、サーバーにつながらない、など。
   - **止める理由:** 必要なツールがないまま、動いているように見せないため（データベースにつながらないときと同じ）。
   - **呼んだときの失敗:** ツールを呼んだときにつながらなかったら、理由の種類だけをモデルに返して、会話を続ける。
8. **手で確かめるコマンドを用意する。** `python -m data_agent.tools.mcp` で、サーバーにつないでツールの一覧を出す。
   - **見せるもの:** 使うツールと使わないツール、引数、説明の先頭を出す。`pack.yaml` に書いたのにサーバーにないツールも出す。
   - **しないこと:** ツールは実行しない。
9. **MCP サーバーになっていない、ふつうの社内 API は、Python で書いたツールから呼ぶ。** 共通の部品（`tools/internal_http.py` の `client`）を使う。鍵は `.env` から読み、社内の認証局を指定でき、リダイレクトを追わない。
   - **→ 取りやめた（2026-11-17）。** オーナーの社内 API は、MCP でラップ済みのため（オーナー: 「API は MCP にラップされているので、そのサンプルはいらないかもしれません」）。
     - **消したもの:** `internal_http.client`、見本のパックの `order_total`、見本のサーバーの `/api/orders`、それらのテスト。
     - **残したもの:** `internal_http.py` の、MCP につなぐための部品（鍵、`ca_file`、リダイレクトを追わない、つながらない理由）。
     - **見本の Python のツール:** 社内 API を呼ばない計算（税込みの金額、`price_with_tax`）に替えた（ADR-0032）。
     - **また要るようになったら:** 決定 4・5 と同じ守り（鍵は `.env`、`ca_file`、リダイレクトを追わない、`token_env` の名前を確かめる）で作り直す。
10. **チュートリアル用に、社内 API の見本を置く**（`examples/internal_api/server.py`）。
    - **中身:** 架空の受注システムを、HTTPS（自分で作った認証局）と鍵で公開する。MCP の入口と、ふつうの API の入口がある（→ ふつうの API の入口は、決定 9 を取りやめたときに消した）。
    - **起動:** `compose.yaml` の `internal-api-example`。`--profile example` のときだけ起動する。
    - **認証局の秘密鍵:** アプリには渡さない。

## 検討した案

| 案 | 内容 | 判断 |
|---|---|---|
| **A. アプリの中から呼ぶ（`langchain-mcp-adapters`）** | ほかのツールと同じ道を通る | **採用**。確認・ガードレール・回数の上限・監査ログが、そのまま効く。料金なし |
| B. Claude API の MCP コネクタ（Anthropic の側で呼ぶ） | API に、MCP サーバーの URL を渡す | 不採用。ツールの呼び出しがアプリを通らないので、確認もガードレールも効かない。社内の API に届かない（Anthropic から届く URL が要る） |
| C. stdio（アプリの中で、MCP サーバーのプログラムを動かす） | よくある MCP サーバーを、そのまま使える | いまは不採用。アプリのコンテナの中で、別のプログラムが動く。鍵の受け渡しと隔離を、別に考える必要がある。使うときは、別のコンテナで HTTP にして使う |
| D. つながらなくても、起動を続ける | ツールなしで動く | 不採用。必要なツールがないまま、動いているように見える |

## 確かめたこと（2026-11-17）

- **単体テスト（`tests/test_mcp.py`、26 件）:** 社内 API の見本を手元に（http で）立てて、実際に MCP でつないだ。
  - **使うツール:** 書いたツールだけを使う。名前に、サーバーの名前を付ける。
  - **説明:** サーバーの説明を使う。差し替えられる。説明の鍵は伏せる。
  - **書いたツールがない:** 起動を止める。サーバーにあるものを示す。
  - **鍵が違う:** 「鍵が違うか、権限がありません（401）」。
  - **サーバーが止まっている:** 「サーバーにつながりませんでした」。
  - **呼んだときの失敗:** 接続先を出さずに、モデルに返す。
  - **長い結果:** 切る。構造化した結果は捨てる。
  - **設定:** 危ない書き方（`http://`、URL の中のパスワード、鍵をそのまま書いたヘッダー、書き間違い）は、受け付けない。
  - **Python のツールの見本:** 社内 API を呼んで、合計を出す（→ 決定 9 を取りやめたときに、このテストも消した）。
- **HTTPS の確認（Docker の中）:** 見本のサーバーを、自分で作った認証局の証明書で動かして、アプリの起動のときの知らせを確かめた。
  - **正しい鍵と認証局:** 3 つのツールを読み込んだ（サーバーにある 4 つのうち、書いた 3 つ）。
  - **鍵が違う:** 「鍵が違うか、権限がありません（401）」で起動を止めた。
  - **別の認証局 / ca_file なし:** どちらも「サーバーの証明書を確かめられませんでした。ca_file を確かめてください」で止めた。
  - **サーバーが止まっている:** 「サーバーにつながりませんでした」で止めた。
- **依存の点検（`uv audit --frozen`）:** `langchain-mcp-adapters` 0.3.2 を足したあとの 175 個で、見つからなかった。足したのは、このライブラリ 1 つだけ（ほかの依存は、すでに入っていた）。

### 結果

- **画面の回帰確認（`bash tests/e2e/regress.sh`。新しい依存を入れた確認用のイメージ `data-agent:mcp-check` で流した）:** 18 種類・390 項目がすべて通った（`logs/e2e/20261117-073955`、`logs/e2e/20261117-075424`）。新しい確認 `mcp` は 22 項目。
  - **見本のサーバー:** HTTPS で動かした（自分で作った認証局と鍵）。
  - **パック:** 見本のパックで起動した。
  - **確かめたこと:**
    - あいさつがパックのものになる。
    - 読むだけのツールは確かめずに呼べる。
    - 結果の連絡先はマスクされる。
    - 書き換えるツールは確認が出て、拒否すれば書き換わらず、承認すれば書き換わる。
    - 書いていないツール（`delete_order`）は使えない。
    - 鍵を含む引数は送らない。
    - 回数の上限で止まる。
    - Python のツールも HTTPS の社内 API を呼べる（→ 決定 9 を取りやめたあとは、パックの Python のツール（税込みの金額）が使えることを確かめる）。
    - 毎回確認では、MCP のツールも Python のツールも確かめる。
    - 画面の履歴に、連絡先と鍵が残らない。
- **決定 9 を取りやめたあと（2026-11-17）:** 単体テスト 543 件（2 件を消し、見本の Python のツールのテストを 1 件足した）と、画面の回帰確認の `boot`・`mcp`（22 項目）が、すべて通った（`logs/e2e/20261117-202925`）。チュートリアル 5 のテストのひな形も、書いたとおりに通った。

## 分かっている制約

- **鍵は、ヘッダーに入れる決まった値（Bearer など）だけ。** OAuth（ログインして鍵をもらう形）と、クライアント証明書（mTLS）には、まだ対応していない。
- **ツールの一覧は、起動のときに決まる。** サーバーの側でツールが変わったら、アプリを起動し直す。
- **プロキシを通る社内の API には、まだ対応していない。**
- **ツールの説明への仕込みは、使うツールの名指しと、説明の差し替えで守る。** 説明の中の指示は、ガードレールでは見つけられない（見つけるのは、鍵や個人情報の形だけ）。知らないサーバーの説明は、`python -m data_agent.tools.mcp` で読んでから使う。
- **結果に仕込まれた指示は、ほかのツールの結果と同じ守りで扱う。** 役割の文の決まり、確認、送る前の確かめが、それに当たる。MCP の結果を使う攻撃の点検は、本物のモデルではまだ測っていない（`evals/redteam` に、まだ入れていない）。
- **見本のサーバー（`examples/internal_api/`）は、手元で試すためのもの。** 本番では使わない。
