# ADR-0008: 調査・分析エージェントは「エージェント1体＋ツール＋チェック役」から始める

- **状態:** 採用
- **日付:** 2026-11-13
- **決定者:** プロジェクトオーナー
- **対象:** 調査・分析エージェント（customer_needs_agent とその後継）

## 状況

問い合わせの内容に沿って会社や顧客を調べ、分析して答えるエージェントを考えています。必要な機能は次の7つです。

1. データベースから取引データを取る
2. RAG からセールスコメントを抽出する
3. Web から IR・決算・プレスリリース・業界情報・統計を取る
4. 有料で入手したリサーチ会社の会社情報を取る
5. 集めた情報を、問い合わせの内容に沿って分析する
6. 情報収集から分析出力までの計画と、ゴール基準を示す
7. 出力が正しいか、出典があるかをチェックする

論点は「機能ごとに別のエージェントが必要ではないか。そこまで複雑にしなくてもよいのか」でした。

## 決定

**エージェント1体に、データ取得用のツールと、独立したチェック役を付けた構成から始めます。** 機能ごとにエージェントを分けることはしません。

| 機能 | 何にするか |
|---|---|
| 1. 取引データを取る | ツール（読み取り専用の SQL） |
| 2. セールスコメントを抽出する | ツール（検索） |
| 3. Web から情報を取る | ツール（検索と取得）。読む量が多ければサブエージェントにする |
| 4. 有料リサーチデータを取る | ツール |
| 5. 分析する | メインのエージェント自身 |
| 6. 計画とゴール基準を示す | メインのエージェント自身（TODO とルーブリック） |
| 7. 出力をチェックする | 別のチェック役 |

あわせて、次の3点を決めごとにします。

- **すべてのツールが出典の ID を返す。** URL、レコード ID、資料名、日付などです。これがないと、最後の出典チェックができません。
- **ゴール基準を使い回す。** 最初に計画とゴール基準を人に見せ、同じ基準を最後のチェック役の採点基準にします。
- **有料データの契約を確認する。** リサーチ会社のデータを外部の AI やクラウドに送ってよいかを、使う前に確かめます。

## 検討した選択肢

| | A. 機能ごとにエージェント（7体） | B. 1体＋ツール＋チェック役（採用） | C. 固定の流れ＋フェーズごとのエージェント |
|---|---|---|---|
| **作る量** | 大 | 小 | 大 |
| **情報の受け渡し** | エージェントの間は要約しか渡せず、細部が落ちる | 取引・コメント・決算を1体が突き合わせる | フェーズの間は決まった形のデータで渡す |
| **速度と費用** | 呼び出しが多く、遅くて高い | 少ない | 中 |
| **順序・止め時の保証** | モデル任せ | モデル任せ | コードで保証できる |
| **向いている場面** | 特になし | 1件の問い合わせに答える調査 | 多数の顧客の抽出と並列の深掘り、監査が必要な業務 |

## B を選んだ理由

- **データを取るだけなら、エージェントである必要がありません。** ツールで足ります。
- **分析は1体で行うほうがうまくいきます。** 複数のデータを同じ頭の中で突き合わせる必要があるためです。
- **チェックだけは分ける価値があります。** 書いた本人に採点させると甘くなります。出典が実在するかどうかは、コードで機械的に確かめられる部分もあります。

## 複雑にする条件

次の問題が実際に出てから、部品を足します。

- **Web 調査でコンテキストがあふれる:** Web 調査をサブエージェントに分けます。
- **多数の会社を一度に調べたい:** 1社ごとに並列で動かします。
- **順序・止め時・人の確認をコードで保証したい:** 外側を LangGraph の固定の流れにします（選択肢 C）。

## 影響

- 既存の customer_needs_agent は選択肢 C の構成です。エージェント定義が7つ、ノードが9つあり、実行確認はまだです。「多数の顧客から候補を抽出して1社ずつ深掘りする」用途が必要になったときに使います。
- 既存のツールは流用できます。`query_crm`（読み取り専用の SQL）、`get_customer_timeline`（接点履歴）、`search_internal_docs`（社内資料の検索）、`web_search` です。
- 新しく作るものがあります。
  - セールスコメントの RAG 検索。`search_internal_docs` は今はキーワード検索です。
  - 有料リサーチデータ用のツール。
  - 出典の ID を返す形への統一。
