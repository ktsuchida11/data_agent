# ADR-0027: 画面の入口で接続元を確かめ、HTTPS ではクッキーに Secure を付ける

- **状態:** 採用（実装済み）。オーナーが決めた（2026-11-15。「１から３まで順番に対応をおねがいします」）。ADR-0009 の判断待ち（チャット用の接続に、接続元の検査を足すか）への答え
- **日付:** 2026-11-15
- **決定者:** プロジェクトオーナー
- **対象:** data_agent

## 状況

- **チャットの接続には、接続元の検査が効いていなかった**（ADR-0009 で見つけた）。
  - `.chainlit/config.toml` の `allow_origins` は、ふつうの通信（HTTP）の CORS にしか効かない。
  - チャットの接続（WebSocket。`/ws/socket.io`）では、Chainlit が socket.io の接続元の検査を切っている（`cors_allowed_origins=[]`）。
- **守りは、ログインのクッキーの `SameSite=lax` だけだった。** `SameSite` は、ポート番号を区別しない。
  - そのため、同じ Mac で動く別のアプリ（Langfuse の画面など）のページは「同じサイト」とみなされ、ログインのクッキーが付いて送られる。
  - そのどれかに悪いページが出ると、ログイン中の利用者として、チャットにつなげる。エージェントに、ファイルを読む、コードを実行する、データベースを読む、などをさせられる。
  - **本物のブラウザで確かめた**（2026-11-15。下の「確かめたこと」）。守りがない状態では、別のポート（127.0.0.1:3010）のページが、ログイン中の利用者としてチャットにつながった。
- **HTTPS で公開しても、クッキーに `Secure` が付かない。** ADR-0009 で「確かめる」と残していた。
  - Chainlit のコード（`chainlit/auth/cookie.py`）を読むと、`Secure` を付けるのは `SameSite=none` のときだけだった。
  - このままでは、HTTPS で公開しても、ログインのクッキーが、暗号化されない通信（`http://`）でも送られる。

## 決定

画面の入口（ASGI のミドルウェア。`src/data_agent/ui/connection_guard.py`）に、次の 2 つを足す。`ui/app.py` から付ける。

1. **接続元（`Origin`）の検査。** 一覧は、`.chainlit/config.toml` の `allow_origins`（いまは `http://127.0.0.1:8000` と `http://localhost:8000`）。CORS と同じ一覧を使う。
   - `Origin` が付いていて、一覧にないものは断る。チャットの接続（WebSocket と、その代わりの polling）も、ふつうの API も断る。`null` も断る。
   - WebSocket は、受け入れる前に閉じる（サーバーは 403 を返し、接続を作らない）。HTTP は 403 を返す。
   - `Origin` が付いていないもの（同じ画面からの GET、スクリプト、死活監視）は、通す。ブラウザは、WebSocket の接続と、ほかのオリジンからの通信には、必ず `Origin` を付ける。スクリプトは `Origin` を自由に書けるので、断っても守りにならない。
   - 断ったときは、監査ログに `origin_rejected`（通信の種類と、接続元）を残す。
   - 一覧に `*` があるときは、検査しない（起動時に警告を出す）。
2. **HTTPS でのクッキー。** HTTPS で届いた通信の応答では、クッキーに `Secure` を付ける。ロードバランサーが付ける `X-Forwarded-Proto: https` も見る。
   - 付けるだけなので、`X-Forwarded-Proto` を偽られても、守りは弱くならない（偽った本人のクッキーが送られなくなるだけ）。
   - 手元（`http://`）では付けない。付けると、ログインできなくなる。

## 検討した案

| 案 | 内容 | 判断 |
|---|---|---|
| A. 入口のミドルウェアで確かめる | WebSocket・polling・ふつうの API を、同じ一覧で確かめる | **採用**。Chainlit の中を書き換えない。手元の単体テストで試せる |
| B. socket.io の `cors_allowed_origins` を設定する | Chainlit が作った socket.io の設定を、後から書き換える | 不採用。ふつうの API は守れない。Chainlit を上げたときに壊れやすい |
| C. クッキーを `SameSite=strict` にする | 他サイトからの移動でも、クッキーを送らない | 不採用。ポート番号は区別しないので、別のポートのページは防げない |
| D. 何もしない | AWS で 1 つのドメインだけで公開するなら、影響は小さい | 不採用。手元では、Langfuse などのアプリが同じ Mac で動いている |
| クッキー: `CHAINLIT_COOKIE_SAMESITE=none` | Chainlit が `Secure` を付けるようになる | 不採用。他サイトからの通信にも、クッキーが送られるようになる |

## 確かめたこと（2026-11-15）

- **単体テスト**（`tests/test_connection_guard.py`。9 件）:
  - 一覧にない接続元（別のポート、別のサイト、`null`、空）の WebSocket は、受け入れる前に閉じる。
  - 一覧にある接続元（大文字や末尾の `/` の違いを含む）と、`Origin` がないものは通す。
  - HTTP も同じ。`*` なら確かめない。
  - HTTPS（`X-Forwarded-Proto` を含む）のときだけ、すべてのクッキーに `Secure` を付ける。二重には付けない。
  - 全体で 447 件すべて通った。
- **画面と同じ通信での確認**（`tests/e2e/check_origin.py`。偽のモデル。12 項目すべて OK）:
  - 許可した 2 つの接続元からは、チャットにつながり、返事が返る。
  - 別のアプリ（`http://localhost:3000`）と `null` からは、ログイン中のクッキーがあっても、つながらない（WebSocket の申し込みに 403）。
  - 代わりの通信（polling）と、ふつうの API（チャットの一覧）も、別のアプリからは 403、許可した接続元からは 200。
  - HTTPS で届いたログインでは、クッキーに `Secure` が付き、手元のログインでは付かない。断った回は、監査ログに残った。
- **本物のブラウザでの確認**（確認用のアプリを 127.0.0.1:8010 で動かし、別のポート 127.0.0.1:3010 に、チャットにつなぎに行くページを置いた）:

  | 状態 | 別のポートのページから |
  |---|---|
  | ログインしていない | ログインの検査で断られた |
  | ログイン中・守りなし（`allow_origins = ["*"]`） | **ログイン中の利用者として、チャットにつながった** |
  | ログイン中・守りあり | 403 で断られた（ブラウザの表示: `Unexpected response code: 403`）。監査ログに `origin_rejected` が残った |

  守りありのとき、ふつうの画面は、これまでどおり使えた（メッセージを送り、返事が返った）。
- **本番と同じ読み方での起動**（`tests/e2e/check_boot.py`）も通った。
- **画面の回帰確認**（`bash tests/e2e/regress.sh`。この ADR と同じ日にプロジェクトに入れた）: 接続元の検査を付けた状態で、16 種類、321 項目がすべて通った。ふつうの使い方（確認のボタン、コードの実行、データベース、定時実行、過去のチャットなど）は壊れていない。

## 分かっている制約

- **守る相手は、ブラウザの中の悪いページです。** スクリプトは `Origin` を自由に書けるので、ログインのクッキーを盗まれたときは防げません。
- **公開する URL を変えたら、`allow_origins` に足してください。** 足さないと、画面がチャットにつながりません（AWS では、`https://<公開するドメイン>`）。`*` にすると、検査しません。
- **同じオリジンの中の悪いもの（画面に入り込んだスクリプト）は、防げません。** それは、画面のヘッダー（`Content-Security-Policy`。ADR-0020）で防いでいます。
- **HSTS（ブラウザに、いつも HTTPS で来させる設定）は、入れていません。** AWS では、ロードバランサーで付けます。
- Chainlit を上げたときに、チャットの接続の場所（`/ws/socket.io`）や、クッキーの付け方が変わると、確かめ直しが要ります。

## 見直す条件

- Chainlit を上げたとき（`tests/e2e/check_origin.py` を流す）。
- AWS で公開するとき（`allow_origins` に公開する URL を足し、HTTPS での `Secure` を、本物のロードバランサーで確かめる）。
