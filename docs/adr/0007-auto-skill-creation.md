# ADR-0007: 繰り返している操作のスキル化は「検出と下書きは自動、登録は承認制」にする

- **状態:** 採用（実装済み）。オーナーは提案に変更を加えず、続行を指示した。2026-11-16 に、チャットで頼んで下書きを作る入口（「スキル登録」）を足した（→ ADR-0030。登録は承認制のまま）
- **日付:** 2026-11-14（提案は 2026-11-13）
- **決定者:** プロジェクトオーナー
- **対象:** data_agent

## 状況

何度も行っている操作を、自動でスキル（手順書）にしてほしい、という要望があります。

スキルは、以後のプロンプトに読み込まれる指示書です。中身を確かめないまま登録されると、ファイルや過去の会話に紛れた指示が、スキルとして残り続ける恐れがあります。エージェントが `/skills/` に書き込めないようにしているのも、同じ理由です。

## 決定

- **依頼を記録します。** エージェントに渡した依頼文（マスク済み）と、使ったツールの名前です。
- **記録がたまったら、軽量モデルに読ませて、繰り返されている作業を探します。** 自動で行います。
- **見つかった作業ごとに、スキルの下書きを作ります。** これも自動です。
- **登録は、利用者が下書きの中身を見て、ボタンを押したときだけ行います。**
- **見送った下書きは、もう提案しません。**

## 仕組み

| 段階 | 内容 |
|---|---|
| **記録** | 依頼文の先頭 400 文字と、使ったツールの名前を `RequestLog` の表に残す。コマンドのメッセージと、定時実行の依頼は記録しない。チャットを削除すると、その中の依頼の記録も消える |
| **検出のタイミング** | チャットを開いたとき。記録が 5 件以上あり、まだ調べていないか、前回から 24 時間以上たって依頼が 5 件以上増えていれば、裏で調べる。「スキル提案」のコマンドで、その場で調べることもできる |
| **検出** | 過去 60 日・最大 200 件の依頼を、軽量モデル（`FAST_MODEL`）に渡す。3 回以上繰り返されている作業について、名前・説明・手順を決まった形で答えさせる |
| **下書きの確認** | モデルの答えは、そのまま信用しない。名前の形、繰り返しの回数、手順の有無、すでにあるスキルや過去の提案との重複を確かめ、ガードレールでマスクしてから保存する |
| **知らせ** | 承認待ちの下書きがあると、チャットを開いたときに一言知らせる。承認待ちは 3 件まで |
| **登録** | 「スキル提案」のコマンドで、下書きの中身と、当てはまった依頼の例を見せる。「登録する」を押すと、`skills/<名前>/SKILL.md` に書き出す。新しいチャットから使われる |

回数や件数は、`config/security.yaml` の `skill_mining` で変えられます。

| ファイル | 役割 |
|---|---|
| `src/data_agent/features/skill_mining.py` | 記録、検出、下書き、登録 |
| `src/data_agent/ui/skill_commands.py` | コマンドと、登録・見送りのボタン |

## 守り

- **登録は必ず人が承認する。** 下書きができただけでは、スキルは登録されません。
- **登録するのは、利用者が見た中身そのもの。** 提案として保存した中身を、そのまま書き出します。
- **本人の提案だけを操作できる。** ボタンの中身は利用者の側から送られてくるので、ID の形式と持ち主を確かめます。
- **スキルの名前は、英小文字・数字・ハイフンだけ。** フォルダの外に書き出すことはできません。すでにあるスキルは上書きしません。
- **依頼文は、モデルへの指示として扱わせない。** 検出の指示文で、依頼文は資料であると明示しています。

## 検討した選択肢

| | A. 自動で下書き、登録は承認制（採用） | B. 登録まで完全に自動 | C. LangSmith Engine に任せる |
|---|---|---|---|
| **手間** | 登録のたびに1回承認する | なし | 未確認 |
| **安全性** | 人が中身を見てから登録される | 悪意ある指示がスキルとして定着する恐れがある | 未確認 |
| **使えるか** | 使える | 使える | LangSmith の契約が前提になる |

## 確かめたこと（2026-11-14）

使い捨ての PostgreSQL と、偽の検出役を使い、画面と同じ通信で確かめました。偽の検出役は、同じ言葉を含む依頼が 3 件以上あると、決まった下書きを返します。

**確認できたこと**
- 依頼が記録される。コマンドのメッセージは記録されない。
- 記録がたまった状態でチャットを開くと、裏で下書きが作られる。この時点では、スキルは登録されない。
- 次にチャットを開くと、承認待ちがあると知らされる。
- コマンドで、名前・回数・当てはまった依頼の例・手順書の中身が出る。
- 「登録する」を押すと、手順書が `skills/` に書き出される。書き出した手順書を、Deep Agents の仕組みが読み取れる。
- 登録したものと、見送ったものは、もう提案されない。
- 存在しない提案の ID を入れたボタンでは、何も登録されない。
- チャットを削除すると、その中の依頼の記録も消える。
- これまでの機能（定時実行、モデルの切り替え、ガードレール、一覧・再開・削除、アーカイブ・グループ分け）が、引き続き通る。
- 単体テスト 91 件が通る。

**確認していないこと**
- **本物のモデルでの検出。** 軽量モデルに決まった形で答えさせる呼び出しは、まだ一度も本物の API で動かしていません。うまくいかない場合は、コマンドを使ったときにエラーの知らせが出て、アプリのログに記録されます。
- 見つかる下書きの質。どの程度の繰り返しを拾えるか、手順が役に立つかは、使ってみないと分かりません。
- 登録したスキルを、本物のモデルが次のチャットで実際に使うこと。
- ブラウザの画面での見え方。

## 分かっている制約

- **登録したスキルは、全員に効きます。** スキルの置き場所は1つで、利用者ごとには分かれていません。1人で使っている間は問題になりませんが、複数人で使う前に、利用者ごとに分けるか、管理者の承認にするかを決める必要があります。
- **重複は、名前でしか防げません。** 見送った作業が、別の名前で提案し直されることはあり得ます。
- **依頼の記録は、消していません。** 60 日より古い記録は調べませんが、データベースには残ります。
- **登録したスキルの一覧や削除の画面はありません。** 削除するには、`skills/` の中のフォルダを消します。
- **AWS では、`skills/` を書き込めて消えない場所に置く必要があります**（ADR-0009）。

## 次にやること

- [ ] 本物のモデルで、検出から登録までを確かめる
- [ ] 複数人で使う前に、スキルを利用者ごとに分けるかを決める
- [ ] 依頼の記録を残す期間を決める
