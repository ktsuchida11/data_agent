# data-agent（データ分析エージェント）

LangChain Deep Agents + LangGraph で作る、社内のデータ（ファイルやデータベース）を調べて分析するエージェントです。Claude Code の作り方を手本にしています（2026-11-16 に coding_agent から名前を変えた。ADR-0029）。
チャット画面は Chainlit、LLM は Anthropic API を使います。
設計の考え方は、ひとつ上のフォルダの `01_DeepAgents利用法とClaudeCode風エージェントの作り方.md` を参照してください。
全体の仕組み（何でできていて、1 回の依頼がどう流れるか）は、[docs/architecture.md](docs/architecture.md) にまとめています。まずそちらを読むと、この README の各節の位置づけが分かります。
別の用途のエージェントの土台としても使えます。用途ごとに違うもの（役割の文、使うツール、つなぐ社内の API）は用途パック（`packs/<名前>/`）に書きます。手順は [docs/tutorials/](docs/tutorials/README.md) にあります。

## 動かし方
```bash
cd data_agent
uv sync --locked
cp example.env .env         # ANTHROPIC_API_KEY・ログイン情報を設定
uv run chainlit run src/data_agent/ui/app.py --host 127.0.0.1 --port 8000
```
ブラウザで http://127.0.0.1:8000 を開き、`.env` に設定したユーザー名とパスワードでログインします。

### 会話を PostgreSQL に保存する
何も設定しなければ、会話はメモリ上に保存され、再起動で消えます。
手元で動いている Langfuse と同じ PostgreSQL に保存するには、次を1回だけ実行します。
```bash
bash scripts/setup_local_db.sh
```
Langfuse の PostgreSQL の中に、データベース `coding_agent` と、それだけを使えるロールを作り、接続情報を `.env` に追記します。Langfuse 自身のデータベースには手を加えません。
`.env` に `DB_HOST` があれば PostgreSQL に保存し、つながらないときは起動を止めます。

PostgreSQL に保存しているときは、画面の左側に「過去のチャット」の一覧が出ます。
- 一覧からチャットを選ぶと、会話が開き、続きから話せます。
- チャットごとに、名前の変更と削除ができます。削除すると、保存した会話も消えます。
- 一覧は日付ごとに並び、チャットの名前とグループ名で検索できます。

アーカイブとグループ分けは、入力欄で `/` を打つと選べるコマンドで行います。

| コマンド | 動き |
|---|---|
| アーカイブ | いま開いているチャットを、左の一覧から隠す |
| アーカイブ一覧 | 隠したチャットを表示する。ボタンを押すと、一覧に戻る |
| グループ | いま開いているチャットにグループ名を付ける。コマンドを選び、グループ名を書いて送る。一覧では名前の先頭に `[グループ名]` が付く |
| グループ解除 | いま開いているチャットをグループから外す |

コマンドのメッセージは、エージェントには渡りません（`docs/adr/0011-chat-history-sidebar.md`）。

### 定時実行
指定した日時に、依頼を無人で実行します。PostgreSQL に保存しているときだけ使えます。入力欄で `/` を打って選びます。

| コマンド | 動き |
|---|---|
| 定時実行 | 「分 時 日 月 曜日」の5項目と依頼文を書いて送る。内容を確認するボタンが出て、押すと登録される |
| 定時実行一覧 | 登録した予定を表示する。ボタンで、止める・再開する・削除する |

書き方の例（平日の朝9時に実行）:
```
0 9 * * 1-5 README を読んで、今日やることを3行でまとめて
```

- 時刻は日本時間で解釈します（`.env` の `SCHEDULE_TIMEZONE` で変えられます）。
- 結果は、左の一覧の「定時実行」グループのチャットとして残ります。開いて、続きを話せます。
- 無人で動くので、確認が必要な操作（ファイルの削除、メモリへの書き込み、外に出したくない情報らしいものを含む Web 検索など。下の「操作の前の確認」）は自動で拒否されます。どの操作が拒否されるかは、登録のときに表示されます。
- 実行の間隔は5分以上、登録できるのは1人20件までです（`config/security.yaml`）。
- アプリが止まっている間は動きません。止まっていた間に過ぎた回は、起動したあとに1回だけ実行します。
- 動くのは依頼文です。依頼文がスキルの説明に当てはまれば、そのスキルの手順で進めます。確実に使わせたいときは、依頼文にスキルの名前を書きます（例: `0 9 * * 1 weekly-report のスキルで、先週の売上をまとめて`）。
- 予定は、この `/` のコマンドからだけ登録できます。ふつうの会話で「毎週月曜に〜して」と頼んでも、予定は作られません（エージェントには、予定を作る道具を持たせていない）。

詳しくは `docs/adr/0006-scheduled-skill-runs.md` にあります。

### スキルの提案と登録
同じ種類の依頼を繰り返していると、スキル（手順書）の下書きを自動で作ります。チャットで頼んで下書きを作ることもできます。PostgreSQL に保存しているときだけ使えます。

- 依頼が5件以上たまると、チャットを開いたときに裏で調べます。3回以上繰り返されている作業があれば、下書きを作ります。
- 下書きがあると、チャットを開いたときに知らせが出ます。
- 入力欄で `/` を打って「スキル提案」を選ぶと、下書きの中身を見られます。「登録する」を押すと `skills/` に書き出され、新しいチャットから使われます。「見送る」を押すと、同じ名前ではもう提案されません。
- 登録は、ボタンを押したときだけ行います。下書きができただけでは、スキルは増えません。
- 好きな内容のスキルは、`/` の「スキル登録」から頼めます。「どんな手順書にしたいか」を書いて送ると、下書きを作って見せます（例: `weekly-sales: 毎週の売上を地域ごとにまとめる`。先頭の「名前:」は省けます）。「今やった集計を手順書にして」のように、このチャットのやりとりを指して頼むこともできます。登録は、ここでも「登録する」を押したときだけです（ADR-0030）。
- エージェント自身は `skills/` に書き込めない設定です（悪い指示が手順書として残らないように。ADR-0007）。ふつうの会話で「スキルにして」と頼むと、「スキル登録」を使うよう案内されます。
- 好きな内容のスキルを足すときは、`skills/<名前>/SKILL.md` を手で置きます。先頭に `name` と `description` を書き、その下に手順を書きます（例: `skills/python-testing/SKILL.md`）。作り直しは要らず、新しいチャットと定時実行から使われます。

回数や件数は `config/security.yaml` の `skill_mining` で変えられます。詳しくは `docs/adr/0007-auto-skill-creation.md` にあります。

API キーなしで保存まわりを確かめたいときは、偽のモデルで起動できます（`tests/e2e/` の先頭の説明を参照）。まとめて確かめるときは、下の「画面の回帰確認」を使います。

### コードの実行（グラフ・Excel・PowerPoint・PDF）
エージェントが Python のコードを書いて実行できます。コンテナで起動したとき（`docker compose up`）だけ使えます。

依頼の例:
```
/data/sales.csv を地域ごとに集計して、棒グラフと Excel にして
```

- **できること:** データの集計、グラフ（日本語も描ける）、Excel・PowerPoint・Word のファイルの作成、PDF からの文字の取り出し。
- **作ったファイル:** `workspace/outputs/` に保存されます。画像はチャットに表示され、ほかのファイルはチャットからダウンロードできます。
- **動く場所:** 専用のコンテナ（`sandbox/`）の中です。インターネットにも、データベースにも、作業フォルダにもつながっていません。使うファイルは、エージェントが1つずつ渡します。`.env` や鍵ファイルは渡せません。
- **上限:** 1回の実行は既定で 60 秒、最大 300 秒です。メモリは 1GB までです。
- **確認:** 既定では、確認なしで実行します。確認したいときは、画面の設定欄で「毎回確認」を選びます（下の「操作の前の確認」）。どのチャットでも必ず確認したいときは、`config/security.yaml` の `code_execution.require_approval` を `true` にします。

使えるライブラリは、pandas、numpy、matplotlib、openpyxl、xlsxwriter、python-pptx、python-docx、pypdf、pdfplumber、pillow、tabulate です。足すときは `sandbox/requirements.in` に書いて、イメージを作り直します。詳しくは `docs/adr/0016-code-execution-in-sandbox-container.md` にあります。

### データベースからデータを取る（PostgreSQL）
エージェントが、データベースの表を調べて、SQL でデータを取れます。読み取り専用です。

準備（1回だけ）。手元の Langfuse と同じ PostgreSQL にあるデータベースを読ませる場合:
```bash
bash scripts/setup_data_db.sh --sample   # 練習用のデータ（架空の商品・顧客・注文）で試す
```
すでにあるデータベースを読ませるときは、先に、読めなくする列（個人情報）を決めます。
```bash
bash scripts/setup_data_db.sh --columns 名前   # 表と列の一覧を出し、読めなくする列の下書きを作る
open -e config/hidden_columns.名前.txt          # 下書きを確かめて、直す（Mac のテキストエディットで開く）
bash scripts/setup_data_db.sh 名前             # 読めるようにする（下書きに書いた列は、読めなくなる）
```
読み取りだけを許したロール（`coding_agent_reader`）を作り、接続情報を `.env` に追記します。データの中身は変えません。表を足したときや、読めなくする列を変えたときは、同じコマンドをもう一度実行します。別のデータベースの名前で実行すると、読むデータベースが切り替わります。
ほかの場所のデータベース（AWS の RDS など）を読ませるときは、読み取り専用のロールを自分で作り、`.env` に `DATA_DB_*` を書きます（書き方は `example.env`）。

依頼の例:
```
どんな表があるか見せて
地域ごとの売上を月別に集計して、折れ線グラフにして
```

- **できること:** 表と列の一覧、SQL（SELECT）でのデータの取得と集計。
- **結果:** CSV にして `workspace/outputs/` に保存します。モデルに見せるのは先頭の 30 行だけで、全体を使う集計やグラフは、その CSV をコードの実行に渡して行います。
- **書き込めない:** 読み取りだけを許したロールでつなぎ、読み取り専用のトランザクションの中で実行します。管理者のロールでつないだときは、問い合わせを受け付けません。
- **上限:** 1回の問い合わせは 30 秒、10,000 行、10 MB までです（`config/security.yaml` の `database`）。
- **モデルに送られるもの:** 問い合わせの結果の先頭 30 行は、モデル（Anthropic の API）に送られ、会話の履歴にも残ります。
- **個人情報の列:** データベースの側で、列ごとに読めなくします（`config/hidden_columns.<名前>.txt` に、1行に1つ `表.列` と書く）。読めなくした列は、どんな SQL でも読めません。表の一覧では「読めない」と出ます。下書きの印は、列の名前からの推測なので、必ず目で確かめてください。練習用のデータでは、顧客のメールアドレスを読めなくしてあります。顧客の名前は読めます（Web 検索に入れようとすると確かめます。下の「Web 検索の前の確認」）。下書き（`--columns`）でも、人の名前らしい列は読める側にしてあり、見張る列の下書きも一緒に作ります。
- **読めなくし忘れたとき:** メールアドレス、電話番号、口座番号、カード番号、マイナンバーは、モデルに渡る前と、CSV に保存する前にマスクします。氏名と住所は見つけられないので、列で守ってください。

詳しくは `docs/adr/0017-database-read-tool.md` と `docs/adr/0019-personal-data-column-privileges-and-masking.md` にあります。

### Web 検索
エージェントが、Web を検索して、分かったことと出典（URL）を返します。Claude API の Web 検索ツールを使うので、新しい契約や鍵は要りません。

- **料金:** 検索 1,000 回あたり 10 ドル（1回 0.01 ドル）と、検索する役のモデルの利用料がかかります。月額の固定費はなく、使わなければ 0 円です。
- **上限:** 1回の依頼での検索は、最大 25 回です（1回の呼び出しで 5 回まで × 呼び出しは 5 回まで。サブエージェントが検索した分も、合わせて数えます）。`config/security.yaml` の `web_search` で変えられます。
- **検索する役:** チャットのモデルとは別に呼び出します（`.env` の `WEB_SEARCH_MODEL`。既定は Sonnet 5.5）。渡すのは依頼文だけで、作業フォルダやデータベースの中身は見えません。
- **外に出るもの:** 依頼文に書かれたことは、検索語として外に出ます。秘密情報らしい文字列を含む依頼文は、検索しません。社内の数値や文章のように、形の決まっていないものは止められません。そのため、質問文を調べて、外に出したくない情報らしいものがあるときだけ、検索の前に確かめます（`require_approval: auto`。下の「Web 検索の前の確認」）。
- **止める・絞る:** 止めるときは `web_search.enabled` を `false` にします。調べる先を絞るときは `allowed_domains` を設定します。検索のたびに確かめるときは `require_approval` を `true` に、確かめないときは `false` にします（`false` は、質問文を見ずに送ることになるので、おすすめしません）。

詳しくは `docs/adr/0018-web-search-via-claude-api.md` にあります。

### Web 検索の前の確認
Web 検索の質問文は、検索のために外部に送られます。送る前に質問文を調べて、次のものがあるときだけ、画面で確かめます。見つからなければ、確かめずに検索します。

- **手元のデータの写し:** このチャットで読んだファイル・データベースの結果などにあって、自分では書いていない番号やコード、表の値（取引先の名前など）、長い文。
- **見張る言葉:** `private/watch_terms.txt` に書いた言葉と、データベースの顧客の名前などの列の値。自分で書いた場合も確かめます。

確認の画面には、見つかったものと、どこにあったかが出ます。

- **見張る言葉の一覧は、自分で作ります。** `private/watch_terms.example.txt` を `private/watch_terms.txt` という名前で写して、1行に1つずつ書きます。`private/` はイメージに入らず、エージェントからも読めません。書き換えると、次の検索から使われます。「株式会社」などを除いた形（「はまなす商事」）も見張ります。
- **データベースの顧客の名前も見張れます。** 名前の列を `config/watch_columns.<データベース名>.txt` に `表.列` と書いて、`bash scripts/setup_data_db.sh <データベース名>` をもう一度実行します（練習用のデータベースでは `customers.name` が書いてあり、`--sample` で実行します）。その列だけを読める別のロール（`coding_agent_screener`）ができ、アプリが 10 分ごとに読み直します。名前はファイルに書き出しません。初めて実行したときは、`.env` に接続情報が足されるので、アプリを作り直します。データベースに届かないときは、どの検索も確かめます。
- **定時実行では、怪しい検索だけを自動で拒否します。** ふつうの検索は行います。
- **見つけられないものもあります。** 言い換えたもの（「4.82 億円」など）や、ローマ字にした名前は、見つけられません。ファイルの見出しやログのエラー番号を質問に使うと、怪しくなくても確かめることがあります。

詳しくは `docs/adr/0022-web-search-screening.md` にあります。

### モデルの切り替え
入力欄の設定ボタンから、チャットごとにモデルを選べます。

- 選べるモデルは、`.env` の `MODEL_CHOICES` で決めます（既定は Opus 5.5、Sonnet 5.5、Haiku 5.5）。
- 新しいチャットは、`MAIN_MODEL` のモデルで始まります。
- 途中で替えても、会話は続きから話せます。替えた直後の1回は、入力の料金が割引なしになります。
- 選んだモデルはチャットごとに覚えるので、開き直しても同じモデルで続きます（PostgreSQL に保存しているときだけ）。

### 操作の前の確認（承認）
エージェントが操作を実行する前に、画面で「実行してよいですか？」と確かめます。どこまで確かめるかは、入力欄の設定ボタンから、チャットごとに選べます。

| 操作 | 標準 | 毎回確認 |
|---|---|---|
| ファイルの削除 | 確認する | 確認する |
| 長期メモ（`memories/`）への書き込み | 確認する | 確認する |
| ファイルの作成、書き換え | 確認しない | 確認する |
| Web 検索 | 外に出したくない情報らしいものがあるときだけ確認する | 確認する |
| コードの実行、データベースの問い合わせ | 確認しない | 確認する |
| 読むだけの操作（ファイルを読む、表の一覧） | 確認しない | 確認しない |

- 確認の画面には、何をするか、なぜ聞いているか、中身（書き込む内容、コード、SQL、検索の質問文）が出ます。
- 答えは4つです。「承認」「承認（このチャットでは以後確認しない）」「拒否」「拒否して理由を伝える」。理由を書くと、エージェントに伝わります。
- 「以後確認しない」は、削除と長期メモへの書き込みには出ません。チャットを開き直すと、取り消されます。
- 外に出したくない情報らしいものがある Web 検索には、「以後確認しない」は出ません。
- 10 分以内に答えないと、実行しません。確認を待ったまま画面を閉じた場合は、チャットを開き直すと、もう一度聞かれます。
- サブエージェントの操作も、同じように確かめます。調べるだけのサブエージェントは、書き込みができません。
- 新しいチャットは「標準」で始まります。既定を変える、利用者が切り替えられないようにする、「以後確認しない」を出さない、といった設定は、`config/security.yaml` の `approvals` にあります。

詳しくは `docs/adr/0021-approvals-human-in-the-loop.md` にあります。

### 回数の上限
モデルが同じ操作を繰り返し続けて、料金がふくらむのを防ぎます。1回の依頼で、モデルを呼べるのは 60 回、ツールを呼べるのは 120 回までです（`config/security.yaml` の `limits`）。
サブエージェントの分と、確認のあとの続きも、同じ1回の依頼として数えます。上限に達すると、その旨を表示して止まります。「続けて」と送ると、続きから進みます。

### コードを変えたときの確認（料金なし）

コードを変えたら、次の 3 つを通します（ADR-0034）。GitHub に送ると、同じ 3 つを CI（GitHub Actions）も流します（ADR-0036）。

```bash
uv run ruff format .
uv run ruff check .
uv run pytest -q
```

- `ruff format` は、改行や空白などの書き方を揃えます（整形）。
- `ruff check` は、誤りのもとになりやすい書き方、分岐が多すぎる関数、セキュリティの心配がある書き方（bandit と同じ点検）を見つけます。`--fix` を付けると、直せるものを直します。
- 誤検知には、`# noqa: <番号>  理由` と、理由を添えて書きます。
- 依存ライブラリを変えたら、`bash scripts/audit_deps.sh` で既知の脆弱性を調べます。
- 決めたこと（機能を足す・変える・やめる、など）は、`docs/adr/` に残します（ひな形は `docs/adr/template.md`）。
- 変えたところは `git status` と `git diff` で見られます。記録は GitHub の非公開のリポジトリに置いています（ADR-0035）。

### 画面の回帰確認（料金なし）
画面と同じ通信（ログイン・チャットの接続・API）で、確認のボタン、コードの実行、データベース、ガードレール、モデルの切り替え、定時実行、スキルの提案、過去のチャット、返事の照合、接続元の検査、用途パックと MCP（HTTPS の社内 API の見本）などを、偽のモデルでまとめて確かめます。API キーは要らず、料金もかかりません。
```bash
bash tests/e2e/regress.sh
```
- 10 分ほどかかります。確認ごとに、使い捨てのデータベースとコンテナを作り、終わったら消します。手元の Langfuse の PostgreSQL と、動いているアプリには触れません。
- 先にイメージを作っておきます（`docker compose build`）。手元の `src/`・`tests/`・`config/`・`packs/` を重ねて使うので、イメージを作り直さなくても、手元の変更を確かめられます。依存（`pyproject.toml`）を変えたときだけ、作り直します。
- 一部だけ流すときは、名前を並べます（例: `bash tests/e2e/regress.sh origin grounding`）。
- 結果は `logs/e2e/` に残ります。すべて通れば、終了コードは 0 です。

### 安全性の点検（OWASP LLM Top 10）
OWASP LLM Top 10（2025 年版）の項目ごとに、合格基準と結果をまとめてあります（`docs/adr/0020-owasp-llm-top10-review.md`）。
依存ライブラリを変えたときは、既知の脆弱性がないかを確かめます。アプリのライブラリと、コードを実行する環境のライブラリを、まとめて調べます。
```bash
bash scripts/audit_deps.sh
```
- 結果は `logs/audit/` に残ります。終了コードは、0 が「見つからなかった」、1 が「見つかった」、2 が「調べられなかった」です。
- 調べる先は OSV（無料の脆弱性のデータベース）で、送るのはライブラリの名前と版だけです。料金はかかりません。
- ライブラリを変えなくても、脆弱性はあとから見つかります。毎日、自動で調べるように、Mac に登録します（毎日 9 時。見つかったときだけ通知が出ます。時刻は `AUDIT_HOUR=7` のように付けて変えられます）。
```bash
bash scripts/schedule_audit.sh install
```
  状態と最後の結果は `bash scripts/schedule_audit.sh status`、解除は `remove` です。詳しくは `docs/adr/0024-scheduled-dependency-audit.md` にあります。

**指示の乗っ取りへの強さを測る**

ファイル・データベースの値・Web 検索の結果に「AI への指示」を仕込み、エージェントが従うか、従ったときに守りを抜けるかを数えます（攻撃は 21 種類。基準は、貫通率 20% 以下）。
```bash
uv run python -m data_agent.evals.redteam --selftest
uv run python -m data_agent.evals.redteam --model all
```
- 1行目は、点検の仕組みを偽のモデルで確かめるだけで、料金はかかりません。
- 2行目は、本物のモデルを使うので、API の料金がかかります。画面で選べる3つのモデルを測って、約 1 ドルです（2026-11-15 の実測で約 0.95 ドル。`--model all` を外すと、既定のモデルだけを測ります。Opus 5.5 だけなら、約 0.5〜0.65 ドル）。実行の前に目安を表示して、確認を求めます。上限（既定は 10 ドル）に達したら、途中でやめます。
- 2026-11-15 の結果: 画面で選べる 3 つのモデル（Opus 5.5、Sonnet 5.5、Haiku 5.5）とも、従った 0/21、貫通 0/21（`docs/adr/0020-owasp-llm-top10-review.md`）。料金は、3 つ合わせて約 0.95 ドルでした。プロンプトを変えたあとの測り直しでも、同じ結果でした（約 0.69 ドル）。
- 本物の作業フォルダ・長期メモ・Web・データベースには触れません。使い捨てのフォルダと、外につながない代わりの役を使います。
- 結果は画面に出て、詳しい記録が `logs/redteam/` に残ります。プロンプト、モデル、ツールを変えたときは、測り直してください。

**誤情報（作り話）を測る**

手元のファイルと検索結果に、答えがある質問・ない質問・コードを実行できない質問（12 問）を送ります。正しい値を答えるか、答えがないときに「ない」と言えるか、ファイルや検索結果にない数や出典を書かないかを数えます。判定に、別のモデルは使いません。
```bash
uv run python -m data_agent.evals.factcheck --selftest
uv run python -m data_agent.evals.factcheck --model all
```
- 1行目は無料（偽のモデル）。2行目は API の料金がかかります（3 つのモデルで約 0.5 ドル）。
- 基準は案です（正答率 90% 以上、「ない」と言えた割合 90% 以上、作り話 10% 以下）。詳しくは `docs/adr/0025-misinformation-check.md` にあります。
- 2026-11-15 の結果: 3 つのモデルとも、正答 6/6、「ない」と言えた 6/6、作り話 0/12（2 回測った。どちらも、記録を読んで判定の規則を直したあとの判定）。
- 読んだ表から出せる簡単な計算（合計、平均、差など）が合っている数と、確かめ先として案内しただけの URL は、作り話に数えません。画面の「作り話に数えなかったもの」に出るので、記録の返事を読んで確かめてください。
- 詳しい記録は `logs/factcheck/` に残ります。

### Langfuse へのトレースの送信（任意）
モデルに何を渡し、何が返り、どのツールを呼んだかを、Langfuse の画面で追えるようにします。

1. Langfuse の画面で、新しいプロジェクトを作る（例: `data-agent`）。
2. そのプロジェクトの Settings → API Keys で、鍵を作る。
3. `.env` に `LANGFUSE_PUBLIC_KEY`、`LANGFUSE_SECRET_KEY`、`LANGFUSE_BASE_URL` を足す（書き方は `example.env`）。

鍵を設定しなければ、何も送りません。送る内容は、下のガードレールでマスクしてから送ります（`docs/adr/0015-langfuse-tracing.md`）。

- **残す期間:** 送った記録は、90 日が過ぎたら、アプリが 1 日に 1 回消します。日数は `config/security.yaml` の `tracing.retention_days` で変えられます（0 にすると消しません。変えたら作り直します）。消すのは、このアプリが送った記録だけです（`docs/adr/0031-langfuse-trace-retention.md`）。
- 消す対象が何件あるかは、次のコマンドで確かめられます（消しません。`--delete` を付けると、すぐに消します）。
  ```bash
  uv run python -m data_agent.storage.trace_retention
  ```

### ガードレールと監査ログ
形が決まっている情報を見つけて、モデルや保存先に流れないようにします。設定は `config/security.yaml` の `guardrails` にあります。

| 種類 | 既定の扱い |
|---|---|
| 秘密情報（API キー、トークン、秘密鍵） | マスクする。含む内容のファイルへの書き込みは拒否する |
| クレジットカード番号、マイナンバー | マスクする |
| メールアドレス、電話番号、口座番号 | マスクする |

- 守る場所は、利用者の入力、ツールの結果（読んだファイルの中身など）、モデルの返事の3つです。
- マスクしたところは `[マスク済み:秘密情報]` のように表示されます。
- 全角で書いたものや、日本語に続けて書いたもの（「電話は０３（１２３４）５６７８です」）も見つけます。口座番号は、「口座」「普通」などの言葉に続く 7 桁の数字だけです。
- マスクは、アプリの全体に効きます。メールアドレスや電話番号を扱う作業（連絡先の一覧を作るなど）をさせたいときは、`email` や `phone` を `log`（記録だけ）に変えます。
- 独自形式のパスワード、氏名、住所のように、形が決まっていないものは見つけられません。データベースの個人情報は、列ごとに読めなくして守ります（上の「データベースからデータを取る」）。

監査ログは、「誰が・いつ・何をしたか」を1件1行の JSON で標準出力に出します。`"log": "audit"` で始まる行です。会話の中身や、見つけた値そのものは記録しません（`docs/adr/0012-guardrails-and-audit-log.md`）。

### 返事の数の照合（作り話の注記）
データを読んだ回の返事について、返事の数と URL が、読んだ結果やこれまでの発言にあるかを照合します。データを読んだ回とは、データベース・Web 検索・コードの実行を使った回と、CSV などのファイルを読んだ回です。見つからないものがあれば、返事の下に注記を出します。返事は止めません。
- 読んだ表から出せる簡単な計算（合計・平均・差など）は、合っていれば注記を出しません。
- 「〜で確かめてください」「〜で確認できます」のように、確かめ先として案内しただけの URL にも、注記を出しません。
- 注記は画面と保存した会話にだけ付き、モデルには渡りません。
- ツールを呼ぶ前に話した文も含めて、その回の返事をすべて照合します。注記は、その回の最後の返事の下に 1 つだけ出ます。
- 定時実行の返事も、同じ決まりで照合します。注記は、結果のチャットの返事の下に残ります。
- 設定は `config/security.yaml` の `grounding` にあります（`enabled: false` で止められます）。
- 数のない作り話（「増えました」など）や、根拠にある数の取り違えは見つけられません（`docs/adr/0026-grounding-note-on-replies.md`）。

### 接続元の検査
画面を開いた場所（オリジン）が、`.chainlit/config.toml` の `allow_origins` にない通信は、チャットの接続も API も断ります。同じ Mac で動く別のアプリ（Langfuse の画面など）のページから、ログイン中のあなたとしてチャットにつながれるのを防ぐためです。
- いまの一覧は `http://127.0.0.1:8000` と `http://localhost:8000` です。別の URL で開くときは、一覧に足してください（足さないと、画面がつながりません）。
- HTTPS で公開したときは、ログインのクッキーに `Secure` を付けます（`docs/adr/0027-origin-check-and-secure-cookie.md`）。

### コンテナで動かす
AWS（ECS）に載せる前の確認用です。`.env` はイメージに入れず、起動時に渡します。
会話は Langfuse と同じ PostgreSQL に保存するので、Langfuse が起動している必要があります。
```bash
cd data_agent
cp example.env .env             # まだ作っていない場合。ANTHROPIC_API_KEY・ログイン情報を設定
bash scripts/setup_local_db.sh  # 初回だけ。会話の保存先を作る
docker compose up --build       # 止めるときは Ctrl+C。片付けは docker compose down
```
開く URL とログイン方法は上と同じです。`workspace/` と `memories/` は手元のフォルダをそのまま使います。
コードを実行するための専用のコンテナ（`sandbox`）も、一緒に起動します。
データベースを読ませる設定（`scripts/setup_data_db.sh`）をしてあれば、コンテナの中からも同じデータベースにつながります。
`uv run` で起動したものと同時には動かせません（どちらも 8000 番ポートを使うため）。

### 別の用途に使う（用途パック）
用途ごとに違うもの（名前とあいさつ、役割の文、使うツール、MCP サーバー）は、用途パック（`packs/<名前>/pack.yaml` と `SYSTEM.md`）に書きます。どのパックを使うかは、`.env` の `AGENT_PACK` で選びます（書かなければ `data`。いまのデータ分析）。守りの設定（`config/security.yaml`）は、どのパックにも共通です（`docs/adr/0032-use-case-packs-and-tool-registry.md`）。

| パック | 用途 |
|---|---|
| `packs/data/` | データ分析（毎日使っているもの） |
| `packs/internal_api_example/` | 見本: 社内の受注システム（の見本）を、MCP と Python のツールで調べる |

いまのパックの中身（使うツールと、それぞれの確認・回数の上限など）は、次で確かめられます（何も実行しません）。
```bash
uv run python -m data_agent.tools.registry
```
ツールの扱い（確認、回数の上限、送る前の引数の確かめ、返事の照合、確認の画面の名前）は、ツールと一緒に `tools/registry.py` の `ToolPolicy` に書きます。Python のツールは、パックの `tools.py` に `@agent_tool` を付けて書きます。
ガードレールは、どのツールの結果にも効きます。用途ごとの番号（社員番号など）は、`config/security.yaml` の `guardrails.custom_rules` に正規表現で足せます（試すときは `uv run python -m data_agent.safety.guardrails "文章"`）。

### 社内 API をつなぐ（MCP）
社内の API が MCP サーバー（HTTP）になっていれば、パックの `pack.yaml` の `mcp_servers` に書くだけでつなげます（`docs/adr/0033-mcp-internal-api-over-https.md`）。
- **使うツール:** `tools` に書いたものだけ。名前は「サーバー__ツール」です。
- **確認:** 既定は「毎回」です。
- **鍵:** `.env` に置き、`pack.yaml` には `${環境変数名}` と書きます。
- **社内の認証局の証明書:** `private/` に置き、`ca_file` で指定します。
- **つながらないとき:** 起動を止めて、理由を知らせます。

```bash
docker compose run --rm data-agent python -m data_agent.tools.mcp
```
サーバーにつないで、ツールの一覧と説明を出します（実行はしません）。
手元で試すための社内 API の見本（架空の受注システム。HTTPS と鍵つき）は、`docker compose --profile example up -d internal-api-example` で起動します（[チュートリアル 4](docs/tutorials/04-mcp.md)）。社内の API は、MCP でつなぐ前提です（Python のツールから API を直接呼ぶ部品は、用意していません）。計算などのツールは、Python で足せます（[チュートリアル 5](docs/tutorials/05-python-tool.md)）。

## エージェントから見えるもの
| 仮想パス | 実体 | 権限 |
|---|---|---|
| `/` | `workspace/` | 読み書き可（`.env`・鍵ファイル・`.git/` は読み書き禁止、削除は必ず確認） |
| `/memories/` | `memories/` | 読み取り可、書き込みは必ず確認 |
| `/skills/` | `skills/` | 読み取りのみ |

`config/`・`.env`・`src/` はどこにもマウントしていないので、エージェントからは見えません。

データベースの問い合わせの結果（CSV）も、`/outputs/` に保存されます。
